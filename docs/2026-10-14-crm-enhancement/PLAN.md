# 샌드비 CRM 고도화 계획서

> 작성일: 2026-10-14
> 목적: 이메일 발송 지표 고도화 + 행동 기반 후속 대응 자동화

---

## 1. 현황 분석

### 현재 할 수 있는 것
| 영역 | 상태 | 설명 |
|------|------|------|
| 이메일 발송 | O | AI 자동발송, 템플릿 발송, 후속발송 |
| 클릭 추적 | O | 이메일 내 링크 클릭 시 clickId 발급 → 사이트 방문 연결 |
| 사이트 행동 추적 | O | 페이지뷰, 영역 체류, 버튼 클릭, 커스텀 이벤트 |
| 고객 여정 알림 | O | 사이트 활동 종료 후 구글챗으로 카드 알림 |
| 회신 감지 | O | Gmail 연동으로 회신/바운스 자동 분류 |
| 발신 건강도 | O | 바운스율, 인증 실패 모니터링 |
| 수신거부 | O | 워크스페이스 단위 수신거부 관리 |

### 현재 못 하는 것 (= 기회)
| 영역 | 설명 |
|------|------|
| 사업간 성과 비교 | 어떤 사업이 잘 보내고 있는지 한눈에 비교 불가 |
| AI 규칙별 성과 | 어떤 프롬프트/규칙이 클릭률이 높은지 비교 불가 |
| 행동 기반 자동 후속 | 사이트에서 특정 행동한 사람에게 자동으로 후속 메일 불가 |
| 고객 세그먼트 | "가격 페이지 본 사람", "3분 이상 체류한 사람" 등 그룹핑 불가 |
| 통합 타임라인 | 한 고객의 메일수신→클릭→방문→행동→회신 이력 한눈에 보기 불가 |
| 파이프라인 관리 | 리드 단계(신규→접촉→상담→계약)를 체계적으로 관리 불가 |
| 알림 기반 빠른 조치 | 구글챗 알림 보고 → 샌드비에서 바로 조치할 수 있는 UI 부족 |

## 2. 제안 기능 (우선순위 순)

### Phase 1: 지표 고도화 (1~2주)
> 지금 쌓이는 데이터로 바로 만들 수 있는 것들

#### 1-1. AI 규칙별 성과 대시보드
- **목적**: 어떤 AI 규칙(프롬프트)이 효과적인지 비교
- **지표**: 규칙별 발송 수 / 성공률 / 클릭 수 / 클릭률
- **드릴다운**: 규칙 → 일자별 → 파티션별
- **비교 뷰**: 같은 사업 내 규칙 A vs B 클릭률 비교
- **활용**: "이 사업은 A 프롬프트가 클릭률 8%인데 B는 2%야. B 프롬프트 바꿔봐"

#### 1-2. 사업별 종합 리포트
- **목적**: 사업간 이메일 효율 한눈에 비교
- **지표**:
  - 일일 발송량 추이 (기간 비교 가능)
  - 클릭률 추이
  - 사이트 방문 전환율 (클릭 → 실제 사이트 방문)
  - 고객 여정 알림 발생 수 (= 의미 있는 방문)
  - 회신율 (회신 수 / 발송 수)
- **활용**: "이 사업은 발송은 많은데 클릭률이 다른 사업의 절반이야. 프롬프트 점검 필요"

#### 1-3. 후속발송 성과 분석
- **목적**: 1차 메일 vs 후속 메일 효과 비교
- **지표**: 단계별(1차/2차/3차) 클릭률 비교
- **구분**: 클릭한 사람 후속 vs 안 클릭한 사람 후속
- **활용**: "클릭 안 한 사람 후속이 오히려 클릭률이 높아. 후속 전략 유지"

---

### Phase 2: 행동 기반 세그먼트 (2~3주)
> 사이트 활동 데이터를 활용한 고객 그룹핑

#### 2-1. 행동 세그먼트 빌더
- **목적**: 특정 행동을 한 고객만 모아서 보기
- **조건 예시**:
  - "가격 페이지를 본 사람"
  - "3분 이상 체류한 사람"
  - "상담 버튼을 클릭한 사람"
  - "2회 이상 재방문한 사람"
  - "메일 클릭 후 사이트에서 아무 행동 없이 나간 사람"
- **결과**: 조건에 맞는 레코드 목록 → 후속 액션 가능
- **DB 변경**: 없음 (기존 tracker 테이블 조회만)

#### 2-2. 세그먼트 기반 일괄 액션
- **목적**: 세그먼트된 고객에게 바로 후속 조치
- **액션 종류**:
  - 후속 이메일 발송 (AI 규칙 또는 템플릿 선택)
  - 파티션 이동 (예: "핫리드" 파티션으로)
  - 담당자 배정
  - 태그/메모 일괄 추가
- **활용**: "가격 페이지 본 사람 15명 → 가격 안내 후속 메일 바로 보내기"

---

### Phase 3: 자동화 트리거 (3~4주)
> 특정 행동이 감지되면 자동으로 후속 조치

#### 3-1. 행동 트리거 규칙 엔진
- **목적**: "이런 행동을 하면 → 이런 액션을 자동 실행"
- **트리거 조건**:
  - 여정 단계 도달 (예: "신청 시작" 단계 도달 시)
  - 특정 페이지 방문 (예: 가격 페이지)
  - 특정 버튼 클릭 (예: 상담 신청 버튼)
  - 체류 시간 기준 (예: 5분 이상 체류)
  - 재방문 감지 (예: 24시간 내 재방문)
- **자동 액션**:
  - 후속 이메일 발송 (맞춤 프롬프트)
  - 구글챗 알림 (담당자 태그)
  - 레코드 필드 값 변경 (예: 상태를 "핫리드"로)
  - 파티션 이동
- **활용 시나리오**:
  - "가격 페이지 보고 나간 사람에게 30분 후 가격 안내 메일 자동 발송"
  - "상담 버튼 클릭했지만 폼 제출 안 한 사람에게 1시간 후 '도움이 필요하신가요?' 메일"
  - "3회 이상 재방문한 사람은 자동으로 '관심 고객' 파티션으로 이동"

#### 3-2. 트리거 실행 이력 & 모니터링
- **목적**: 자동화가 잘 동작하는지 확인
- **내용**: 트리거 발동 횟수, 액션 성공/실패, 대상 고객 목록
- **활용**: "이 트리거가 하루에 50번 발동하는데 클릭률이 1%야 → 조건을 좁혀야"

---

### Phase 4: CRM 워크플로우 강화 (4~6주)
> 영업 프로세스 자체를 체계화

#### 4-1. 고객 활동 타임라인
- **목적**: 한 고객의 모든 활동을 시간순으로 한눈에 보기
- **포함 이벤트**:
  - 메일 수신 (어떤 메일을, 언제)
  - 메일 클릭 (어떤 링크를, 언제)
  - 사이트 방문 (어떤 페이지를, 얼마나)
  - 버튼/영역 활동 (어떤 버튼을, 어떤 영역을)
  - 회신 (어떤 내용으로)
  - 담당자 조치 (상태 변경, 메모)
  - 알림톡 수신
- **UI**: 레코드 상세 페이지 내 타임라인 탭
- **활용**: 담당자가 전화하기 전에 "이 고객이 지금까지 뭘 했는지" 즉시 파악

#### 4-2. 리드 파이프라인 보드
- **목적**: 영업 단계별 리드 현황을 칸반 보드로 관리
- **단계 예시**: 신규 → 접촉 시도 → 상담 중 → 제안 완료 → 계약
- **기능**:
  - 드래그 앤 드롭으로 단계 이동
  - 단계별 리드 수, 예상 매출
  - 체류 기간 표시 (이 단계에 며칠째인지)
  - 오래 머문 리드 자동 하이라이트
- **DB 변경 필요**: 파이프라인 설정 테이블 (개발자 협의 필요)

#### 4-3. 담당자 성과 대시보드
- **목적**: 담당자별 후속 대응 현황 파악
- **지표**:
  - 배정된 리드 수
  - 평균 응답 시간 (알림 → 첫 조치)
  - 처리 완료율
  - 전환율 (배정 → 계약)
- **활용**: "A 담당자는 평균 2시간 내 조치하는데 B는 이틀 걸려"

## 3. 기술 제약 및 주의사항

### DB 변경 없이 가능한 것 (Phase 1~2)
- 기존 테이블 SELECT만으로 집계/분석 가능
- 새 API 라우트 + 프론트 페이지만 추가
- `READONLY_DATABASE_URL`로 운영 DB 읽기 전용 접근

### DB 변경이 필요한 것 (Phase 3~4)
| 기능 | 필요한 테이블 | 설명 |
|------|-------------|------|
| 행동 트리거 규칙 | `journey_trigger_rules` | 트리거 조건 + 액션 정의 저장 |
| 트리거 실행 이력 | `journey_trigger_logs` | 발동 기록 |
| 세그먼트 저장 | `saved_segments` | 저장된 필터 조건 |
| 파이프라인 설정 | `pipeline_stages` | 단계 정의 |
| → **개발자님 협의 필수** | | |

### 운영 DB 안전성
- 읽기 전용 API는 `READONLY_DATABASE_URL` 사용 (현재 적용됨)
- 쓰기가 필요한 기능은 개발 DB에서 테스트 후 운영 반영

## 5. 즉시 활용 시나리오

### 시나리오 A: "발송량은 많은데 클릭이 안 나오는 사업 잡기"
1. 발송 통계 탭에서 사업별 클릭률 비교 (현재 구현됨)
2. 클릭률 낮은 사업 → AI 규칙별 성과 확인 (Phase 1-1)
3. 낮은 규칙의 프롬프트 수정 지시

### 시나리오 B: "가격 페이지 본 사람에게 바로 후속"
1. 행동 세그먼트: "가격 페이지 방문 + 아직 계약 안 함" (Phase 2-1)
2. 해당 고객 목록 → 가격 안내 후속 메일 일괄 발송 (Phase 2-2)
3. 또는 자동 트리거 설정: 가격 페이지 방문 시 30분 후 자동 발송 (Phase 3-1)

### 시나리오 C: "상담 버튼 눌렀는데 제출 안 한 사람 잡기"
1. 트리거: 상담 버튼 클릭 + 10분 내 폼 제출 없음 (Phase 3-1)
2. 자동 액션: "상담 신청이 중단된 것 같습니다" 후속 메일
3. 동시에 담당자에게 구글챗 알림

### 시나리오 D: "핫리드 빠르게 처리하기"
1. CRM 관리 페이지에서 긴급/높음 알림 확인 (현재 구현됨)
2. 고객 타임라인에서 행동 이력 확인 (Phase 4-1)
3. 파이프라인 보드에서 단계 이동 (Phase 4-2)

## 6. 예상 효과

| 기능 | 기대 효과 |
|------|----------|
| AI 규칙별 성과 | 효과 없는 프롬프트 빠르게 교체 → 전체 클릭률 향상 |
| 사업별 비교 | 부진한 사업 조기 발견 → 담당자 코칭 |
| 행동 세그먼트 | 관심 있는 고객만 선별 → 후속 메일 정밀 타겟팅 |
| 자동 트리거 | 골든타임 내 자동 후속 → 전환율 향상 |
| 고객 타임라인 | 담당자 통화 전 맥락 파악 → 상담 품질 향상 |
| 파이프라인 보드 | 영업 프로세스 가시화 → 관리 효율 |
