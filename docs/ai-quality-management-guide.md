# AI 품질 관리 기능 설명서

## 개요

AI 품질 관리는 **AI가 자동으로 보내는 이메일의 품질을 관리하는 도구**입니다.
이메일 메뉴 > "AI 품질" 탭에서 접근할 수 있으며, 관리자만 사용 가능합니다.

---

## 먼저 알아야 할 것: 메일 종류 2가지

### 1. 첫 소개 메일 (initial_email)
- AI 자동발송 규칙으로 보내는 메일
- 새 레코드가 등록되거나 조건을 만족하면 AI가 자동으로 작성해서 발송
- `/email?tab=ai-auto` 에서 규칙을 관리하는 그 메일

### 2. 방문 감사 메일 (visit_ack)
- 트래커로 **우리 사이트를 방문한 사람**에게 자동으로 보내는 감사 메일
- "방문해 주셔서 감사합니다" 라는 제목으로, 사이트에 7초 이상 머문 방문자에게 발송
- AI가 방문자의 회사/행동을 참고해서 개인화된 감사 문구를 작성
- 이미 CRM에 등록된 레코드(이메일이 연결된 방문자)에게만 발송
- 환경변수(`EMAIL_VISIT_ACK_MODE`)로 켜고 끔

**핵심 차이:** 첫 소개 메일은 "처음 연락하는 메일", 방문 감사 메일은 "사이트 방문 후 감사 인사 메일"

---

## 탭별 상세 기능

### 탭 1: 자동 관찰

#### 뭐하는 탭인가
AI가 메일을 보낼 때마다 **자동으로 쌓이는 성과 리포트**. 직접 뭔가 할 필요 없이, AI 발송이 일어나면 알아서 데이터를 모아서 보여줍니다.

#### 보여주는 지표들
| 지표 | 뜻 | 왜 중요한지 |
|------|-----|-------------|
| 준비 완료 / 전체 작업 | AI가 문구를 만든 건수 | 전체 중 몇 건이 성공적으로 만들어졌는지 |
| 준비 중 / 검토 대기 | 아직 만들고 있는 건 / 검토가 필요한 건 | 밀려있는 작업이 있는지 확인 |
| 첫 시도 성공률 | AI가 한 번에 문구를 잘 만든 비율 | 낮으면 AI가 어려워하고 있다는 뜻 |
| 30분 내 준비율 | 30분 안에 문구가 완성된 비율 | 낮으면 발송이 지연되고 있다는 뜻 |
| 준비 소요 p95 / p99 | 문구 생성에 걸리는 시간 (상위 5%/1% 기준) | 대부분 빨라도 간혹 느린 게 있는지 |
| 동일 본문 비율 | AI가 비슷한 문구를 반복하는 비율 | 높으면 AI가 다양하게 못 쓰고 있다는 뜻 |
| 가장 많이 쓴 질문 비율 | 특정 질문을 반복하는 비율 | 높으면 변주가 부족 |
| AI 생성 비용 | 건당 AI API 호출 비용 (원) | 비용 관리 |

#### 자동 후보 준비와 실험 패널 (CopyAutomationPanel)

**뭐하는 건지:**
AI가 **더 좋은 메일 문구를 스스로 찾아보는 자동화 시스템**입니다.

**흐름:**
1. AI가 현재 쓰고 있는 지침(기존)을 분석
2. AI가 **더 나은 후보 지침**을 스스로 작성
3. 기존 vs 후보로 **가상 문구 80건**을 생성해서 비교
4. AI가 자체 검토 (자연스러움, 사실성, 목적 적합성)
5. 결과가 좋으면 → 첫 소개 메일은 **A/B 실험**으로 넘기고, 방문 감사 메일은 **적용 대기**로 남김
6. **최종 적용은 항상 사람이 결정** (자동으로 바뀌지 않음)

**설정 항목:**
- **자동 준비 사업**: 어떤 워크스페이스에서 자동 준비를 돌릴지
- **첫 메일 실험 진행 방식**: "자동으로 개설·시작" vs "사람이 직접 개설·시작"
  - 자동: 후보가 좋으면 바로 A/B 실험 시작
  - 수동: 후보가 준비되면 사람에게 알려주고, 사람이 실험을 시작

**각 단계 상태:**
| 상태 | 뜻 |
|------|-----|
| 후보 작성 중 | AI가 새로운 지침 후보를 만들고 있음 |
| 가상 문구 생성·검증 중 | 기존 vs 후보로 가상 문구를 만들어서 비교 중 |
| AI 문구 검토 중 | AI가 만든 문구의 품질을 자체 검토 중 |
| 실험 준비 완료 | 검토 통과, A/B 실험을 시작할 수 있음 |
| 실험·관찰 진행 중 | 실제 고객에게 A/B로 보내고 있는 중 |
| 사람의 적용 대기 | 결과가 나왔고 사람이 적용할지 결정해야 함 |
| 관리자 적용 완료 | 새 지침이 적용됨 |
| 기존 지침 유지 | 후보가 기존보다 좋지 않아서 기각됨 |
| 준비 보류 | 문제가 있어서 중단됨 |

**버튼들:**
- **이 사업 자동 준비 켜기/끄기**: 자동 후보 준비를 활성화/비활성화
- **결과 검토 후 적용**: "적용 대기" 상태인 후보를 검토하고 실제 적용
- **실험 초안 만들기**: 수동 모드일 때 A/B 실험을 직접 개설
- **기존 지침 유지하고 종료**: 후보를 기각하고 기존 지침을 계속 사용

### 탭 2: 작성 지침

#### 뭐하는 탭인가
AI가 메일을 쓸 때 따라야 할 **톤, 규칙, 성능 기준**을 버전별로 관리하는 곳.

#### 지침 버전 하나에 들어있는 것
- **지침 내용**: AI에게 주는 프롬프트 ("이런 식으로 써라")
- **필수 의미**: 메일에 반드시 담아야 할 내용 (예: "방문 감사", "추가 문의 안내")
- **금지 표현**: 절대 쓰면 안 되는 표현 (예: "무료", "할인")
- **모델**: 어떤 AI 모델을 쓸지
- **본문 글자 수 제한**: 최대 몇 자까지
- **성능 기준**: 95% 생성 시간 몇 초 이내, 첫 시도 성공률 몇% 이상

#### 버전 상태
| 상태 | 뜻 | 색깔 |
|------|-----|------|
| draft | 만들기만 하고 아직 평가 안 함 | - |
| evaluated | 자동 평가 완료, 사람 승인 대기 | - |
| approved | 승인됨, 실제 발송에 사용 가능 | 활성 |
| retired | 사용 종료 (새 메일에 안 씀, 기존은 유지) | 비활성 |
| blocked | 문제 발견, 긴급 차단 | 위험 |

#### 버튼들
- **복제하여 수정**: 기존 지침을 복사해서 새 버전으로 만듦. 원본은 그대로 보존. "수정"이 아니라 항상 "새 버전"을 만드는 방식 (이력 관리)
- **새 연결에서 사용 종료**: 이 지침을 앞으로 새 메일 만들 때 안 쓰겠다는 것. 이미 이 지침으로 만들어둔 메일은 그대로 발송됨. 되돌릴 수 있음
- **평가 확인 후 승인**: 품질 평가(탭4)를 통과한 지침을 실제 발송에 사용하겠다고 최종 승인
- **문제 버전 차단**: 이 지침에 심각한 문제가 발견돼서 즉시 사용 중단. 이 지침으로 아직 안 보낸 메일은 전부 보류됨. 차단 이유를 10자 이상 입력해야 함

#### 자동 후보 (automatic_evaluation)
자동 준비 패널에서 AI가 스스로 만든 지침 후보. 사람이 만든 게 아니라 AI가 기존 지침을 분석해서 개선안을 제안한 것. "자동 평가 · 사람 검수와 별개"라는 뱃지가 붙음

#### 기존 설정 자동 등록 (existing_configuration)
시스템이 현재 AI 자동발송 규칙의 설정을 자동으로 지침 형태로 기록해둔 것. 기존에 쓰던 설정의 스냅샷

### 탭 3: 지식 근거

#### 뭐하는 탭인가
AI가 메일에 **사실로 쓸 수 있는 정보**를 관리하는 곳. AI가 없는 얘기를 지어내지 않도록, 여기 등록된 정보만 활용하게 함.

#### 지식 버전 하나에 들어있는 것
- **사업명**: 회사/사업 이름
- **제품 사실 (claims)**: 메일에 쓸 수 있는 사실 목록
  - 각 사실마다 **텍스트** + **근거 URL** + **확인 날짜** + **용도** (첫 소개용/방문 감사용)
  - 예: "고객사 500곳 보유" + https://회사홈페이지.com/about + 2026-10-01 확인 + 첫 소개 메일용

#### 왜 필요한가
AI가 "저희는 업계 1위입니다" 같은 근거 없는 말을 하지 않도록. 여기 등록된 사실만 메일에 활용할 수 있음.

#### 버튼은 작성 지침과 동일
복제하여 수정 / 새 연결에서 사용 종료 / 근거 확인 후 승인 / 문제 지식 차단

---

### 탭 4: 품질 평가

#### 뭐하는 탭인가
새로 만든 작성 지침이 실제로 좋은 문구를 만드는지 **테스트**하는 곳. 실제 고객에게 보내지 않고 가상으로 테스트.

#### 평가 방식
1. **기준 지침(기존) vs 후보 지침(새것)**을 선택
2. 2개 사업 × 20개 가상 상황 × 5회 × 2개 버전 = **400건의 가상 메일 생성**
3. 자동으로 측정하는 것들:
   - 첫 시도 성공률
   - 생성 소요 시간 (p95, p99)
   - 30분 내 준비율
   - 기존/후보 각각의 비용
4. **80건을 사람이 블라인드 평가**:
   - 어느 버전인지 안 알려주고 문구를 제시
   - 자연스러움 / 사실성 / 목적 적합성 각각 1~5점
   - 2명이 독립적으로 평가
   - 점수 차이가 크면 합의 필요
5. 기준을 통과하면 → 작성 지침 탭에서 승인 가능

#### 부하 성능 측정 (개발자용)
동시에 많은 메일을 만들 때 서버가 느려지지 않는지 테스트. 분당 6건을 30분간 + 30건 동시 요청을 3번 반복. **운영자는 신경 안 써도 됨.**

---

### 탭 5: 발송 연결

#### 뭐하는 탭인가
승인된 작성 지침 + 지식 근거를 **실제 발송에 연결**하는 곳. "이 워크스페이스의 이 종류 메일은 이 지침과 이 지식으로 만들어라"를 설정.

#### 설정 항목
1. **사업** (워크스페이스 선택)
2. **메일 목적** (방문 감사 메일 / 첫 소개 메일)
3. **AI 자동발송 규칙** (첫 소개 메일일 때만 — 어떤 발송 규칙에 적용할지)
4. **승인된 작성 지침** 선택
5. **승인된 지식** 선택

#### 적용 규칙
- 연결하면 **새로 준비하는 메일부터** 적용
- 이미 만들어둔 메일, 진행 중인 실험의 메일은 바뀌지 않음
- 이전 승인 버전을 다시 선택하면 되돌릴 수 있음

#### 현재 발송 연결
아래쪽에 현재 어떤 연결이 적용 중인지 목록으로 보여줌

---

### 탭 6: 생성 기록

#### 뭐하는 탭인가
AI가 실제로 생성한 메일 문구의 **이력**을 보는 곳. 어떤 지침/지식으로 만들었는지, 성공/실패 여부 등을 확인.

---

### 탭 7: 비용 설정

#### 뭐하는 탭인가
AI 모델별 **토큰 단가**를 설정하는 곳. 자동 관찰에서 "AI 생성 비용 OO원"을 계산할 때 여기 설정된 단가를 사용.

---

## 전체 흐름 요약

```
1. 지식 근거 등록 (회사 정보 입력)
   ↓
2. 작성 지침 만들기 (AI 톤/규칙 설정)
   ↓
3. 품질 평가 (400건 가상 테스트)
   ↓
4. 승인 (사람이 최종 확인)
   ↓
5. 발송 연결 (어떤 메일에 적용할지 설정)
   ↓
6. 자동 관찰 (발송되면 자동으로 성과 추적)
```

또는 자동 준비를 켜면:
```
자동 준비 ON
   ↓
AI가 스스로 후보 지침 작성 → 가상 테스트 → AI 검토
   ↓
방문 감사 메일: 적용 대기 → 사람이 적용
첫 소개 메일: A/B 실험 → 결과 확인 → 사람이 적용
```

## 운영자 관점 요약

### 평소에 볼 것
- **자동 관찰** 탭에서 AI 발송이 잘 되고 있는지 확인
- 첫 시도 성공률이 낮거나, 동일 본문 비율이 높으면 지침 수정 필요

### 가끔 할 것
- **지식 근거** 업데이트 (회사 정보가 바뀌면)
- 자동 준비에서 "적용 대기" 상태가 뜨면 검토 후 적용/기각 결정

### 거의 안 할 것 (개발자 영역)
- 품질 평가 400건 테스트
- 부하 성능 측정
- 비용 설정
- 작성 지침 직접 만들기 (자동 준비가 대신 해줌)
