# 상담 자동 응대와 고객 관리 동선

고객 상담을 열어 고객 정보를 수정하거나 후속 업무를 잡을 때 여러 화면을 오가던 동선을 줄인다. 고객 관리는 고객 목록부터 열리고, 상담 오른쪽 상단에서 프로필을 확인하고 수정할 수 있다.

## 운영 화면

- 상담 상단의 **고객 연락처**와 **AI 응대**는 현재 상담 채널의 사업을 유지한다.
- 배정 수용량·충돌 방지·팀·사이트 상담창·이메일·직원 권한은 **상담 설정**에 모은다. 운영·성과와 내 응대 상태는 그대로 바로 접근한다.
- 상담 오른쪽에 고객 프로필·회사·진행 거래·후속 업무가 먼저 보인다. 메일·사이트 방문 여정은 펼쳐서 확인한다.
- **고객 정보 수정**은 연결된 CRM 고객을 수정한다. 이름이나 입력 이메일만으로 다른 고객을 병합하거나 과거 상담 공개 권한을 늘리지 않는다. 보관된 고객은 수정할 수 없다.
- 거래 단계가 없으면 상담 화면에서 기본 단계(문의접수 → 도입상담 → 제안중 → 계약완료 / 보류·실패)를 검토·저장한 뒤 해당 고객의 거래 작성으로 이어진다. 고객 목록·후속 업무에는 거래 단계 설정이 필요 없다.
- AI 설정은 응대 방식부터 보이며 메일 전용 지식은 기본적으로 숨긴다. **메일 전용 지식도 표시**로 확인할 수 있다.

## 자동 응대 활성화

디하(사업 8, 상담 채널 1)와 백오피스랩(사업 9, 상담 채널 3)의 응대 방식을 `reply`로 설정한다. 승인한 공개 안내 지식 #36 / #37, Claude Haiku 4.5, 사업별 하루 50회 생성 시도 한도를 유지한다.

서버 설정은 `CUSTOMER_AI_WORKER=on`, `CUSTOMER_AI_WORKSPACES=8,9`이다. 명시한 사업만 자동 처리하며 잘못된 사업 목록은 처리하지 않는다. 사업 목록을 생략한 기존 설치는 이전 동작을 유지한다. 상담 AI 화면의 연결 상태도 해당 사업 기준이다. 수동으로 요청하는 초안에는 이 자동 처리 범위를 적용하지 않는다.

새 고객 문의는 10초 후부터 큐에서 처리한다. 승인 근거로 답변 생성 후 별도 근거 검수를 통과한 경우만 전송한다. 상담원 요청·첨부 자료·근거 부족·사용량 부족은 사람에게 인계한다. 인계한 상담과 상담원이 직접 답변한 상담은 자동 응대를 이어가지 않는다. 담당자를 지정하지 않은 경우 수신함의 중요 상담에서 확인한다.

기존 설정 버전의 작업은 최신 설정 검사를 통과하지 못하므로 뒤늦게 전송되지 않는다. 원본 채널톡 보관 상담은 계속 읽기 전용이다. DB 스키마·고객 일괄 병합·이메일 발송 설정 변경은 없다.

## 검수

- 상담 규칙 및 사업 실행 범위 단위 검사 7개.
- 가상 PostgreSQL 엔진의 상담 SQL/API 시나리오 16개: 자동 답변, 인계, 직원 개입, 새 메시지/설정 변경 중 늦은 답변 차단 등.
- 격리 큐 검사: 더 오래 대기한 다른 사업 작업 제외, 이전 설정 작업 폐기, 잘못된 사업 목록 실행 중단. 실제 모델 호출·외부 발송 없음.
- 타입 검사, 변경 파일 lint, 운영 빌드.
- 배포 후 실제 사이트의 명시한 QA 문의로 자동 답변과 인계, 고객 프로필 수정 및 후속 업무 동선을 확인한다. 결과는 배포 검수 기록에 별도로 보존한다.

이 변경은 초기 운영 동선 개선이다. 채널톡의 모든 기능이나 동일한 사용성을 구현 완료했다는 의미는 아니다.
