# REPORT — 2026-10-13 email-click-bot-filter

## 한 일

메일 보안 검사기(스캐너)가 링크를 대신 눌러 클릭 수가 부풀려지는 문제를 고쳤다.
- 운영 데이터를 분석해 봇 판정 규칙 R6을 정했다.
  - `early`: 발송 후 15초 안에 누른 클릭
  - `burst`: 같은 발송에서 ±10초 안에 다른 클릭이 2건 이상
  - `ua`: 프로그램이나 검사기의 UA
- 클릭을 기록할 때 `is_bot`·`bot_reason`을 저장한다. 기존 클릭은 마이그레이션 0080이 같은 규칙으로 채웠다.
- 사람 클릭만 세도록 바꾼 곳: 후속 메일 분기, 대시보드·분석, 발송 이력, 통합 로그, MCP, 리드 여정.
- 클릭 칸 표시
  - 사이트에서 행동한 발송: 마우스 아이콘과 강조 테두리
  - 봇 클릭만 있는 발송: 흐린 로봇 아이콘
- 트래커 리드 연결, 깊이 알림, 고객 여정 카드는 일부러 그대로 뒀다.

## 배운 것

- **직접 재현할 수 있으면 먼저 재현한다.** 브라우저로 운영 경로를 밟아볼 수 있었는데 "데이터가 오면 확인"이라며 미뤘다가 사용자에게 지적받았다.
- **drizzle 단일 표 select는 칼럼에 표 이름을 붙이지 않는다** (`buildSelection isSingleTable`). 그래서 서브쿼리 안의 바깥 참조가 늘 참이 된다. 이런 쿼리는 원문 SQL로 쓴다.
- **evidence는 처음부터 저장소 경로와 러너 출력 원문으로 남긴다.** 임시 경로와 요약문 때문에 27건이 게이트에 걸렸다.
- **화면 캡처는 개인정보를 확인한 뒤 증거로 쓴다.** 로컬 사본 캡처에는 고객 이메일이 보였다.
