## 사후 수정 (2026-09-01, 아카이빙 이후)

- **allow 기본 모델을 폐기하고 "더해주기"로 전환.** 운영에서 사용자가 김소연님에게 마케터하이어 권한을 부여하자 **다른 member들이 그 워크스페이스를 못 보게 되는** 문제가 드러났다. 체크박스는 "권한 부여"로 읽히는데 실제 효과는 "체크 안 한 사람에게서 뺏기"였다 — UI와 동작이 정반대
- 원인: `canAccessPartition`이 "덮는 scope가 하나라도 있으면 제한 모드로 전환"(covered)하는 규칙을 썼다. 기존 사용자 동작을 안 바꾸려던 설계였는데, 권한을 걸기 시작하는 순간 그 의도가 뒤집혔다
- 수정: `covered` 개념 제거. 데이터 접근은 member 전원의 기본 능력으로 두고(denyByDefault=false면 무조건 통과), 권한은 **구조 변경(파티션·폴더 생성·수정·삭제)과 예약 등록 설정**에만 필요하도록 좁혔다
- 예약 등록 config route에 denyByDefault 추가 — 원래 관리자 전용이던 기능이라 명시적 부여가 필요하다
- UI 문구도 실제 동작에 맞게 수정. 기존 문구("체크하는 순간 그 대상은 권한 받은 멤버에게만 열립니다")는 사실과 반대였다
- 권한 레벨 라벨 변경: "조회만" → "권한 없음"(기본 데이터 접근만), "편집 가능" → "삭제 제외"
- 실측: 타인에게 ws 권한 부여 후에도 다른 member의 파티션 목록 23개 유지(이전에는 17개로 줄었다). 데이터 조회 200, 권한 없는 파티션 생성 403
