# 직원 상담 초안 보존

## 사용하는 방법

직원 상담함에서 답변이나 내부 메모를 작성하고 파일을 선택한 뒤 다른 문의로 이동해도, 같은 사업의 상담함에 머무르는 동안 문의별 문장과 File 객체를 유지한다. 원래 문의를 다시 열면 선택 파일과 업로드 결과를 그대로 이어서 사용할 수 있다. 답변과 내부 메모는 서로 다른 초안으로 관리한다.

전송을 누르기 전에는 업로드나 메시지 저장을 하지 않는다. 전송 실패 후에도 본문·선택 파일·확인된 업로드 ID를 유지한다. 메시지가 저장됐지만 응답을 받지 못한 경우, 문의를 오갔다가 **직접 다시 전송**하면 같은 요청 ID를 사용한다. 자동 재전송은 하지 않는다. 답변 작성 잠금을 사용 중이면 문의를 다시 열 때 현재 작성 권한을 다시 확인해야 한다.

전송 도중 다른 문의로 이동해도 같은 상담함 범위에서는 이미 누른 전송을 마칠 수 있다. 성공하면 원래 문의의 해당 종류 초안만 비우고, 현재 보고 있는 다른 문의의 문장·파일·선택 상태를 바꾸지 않는다.

## 유지 범위와 한도

- 같은 조직·계정·사업의 현재 상담함에서 유지한다. 조직·계정 전환이 시작되거나 사업 변경, 상담함 이탈, 새로고침, 관측된 응대 권한 회수/401·403이 발생하면 File 객체와 전송 대기 상태를 비운다.
- 상담함 전체의 첨부 초안은 최대 20개, 합계 100MiB다. 메시지별 5개·파일별 20MiB 제한도 유지한다. 새 선택이 한도를 넘으면 기존 초안을 지우지 않고 선택을 거절한다.
- 파일은 메모리에만 보관한다. 기존 문장·AI 출처·이메일 수신자·메모 멘션의 localStorage 정책은 그대로 사용한다. 브라우저를 닫은 뒤 파일 초안을 복원하는 기능은 아니다.
- 범위가 끝나면 진행 중 요청을 중단하고 이후 콜백의 업로드·전송 진행을 막는다. 서버가 이미 저장한 요청까지 되돌리지는 않는다. 범위 정리는 첨부 취소 요청을 보내지 않으며 미전송 업로드는 기존 만료 정책을 따른다.

조직 전환·로그아웃·조직 생성의 쿠키 변경 요청은 순서대로 처리한다. 성공·실패·응답 유실 모두 현재 `/api/auth/me` 확인을 마친 뒤 상담함을 다시 표시한다. 그 확인에 실패하면 사용자와 상담함을 비우고 재인증을 기다린다. 과거 인증 조회 응답이 새 조직 상태를 덮어쓰지 않게 요청 세대를 확인한다.

## 검증과 남은 범위

통합한 제품 파일 10개의 내용이 독립 검수본과 같고, 직원 브라우저 검수에 실제 로드한 소스 225개와 고객 위젯 회귀의 소스 19개가 일치함을 확인했다. 해시는 줄바꿈을 LF로 정규화해 비교한다. `evidence-manifest.json`의 `staffDraftSessionQa`에 명령과 증거 파일·해시를 기록한다.

독립 직원 UI 검수 16개는 실제 `app/inbox/page`·`SessionProvider`·`InboxPage`·`ConversationPane`·`OrgSwitcher`, 실제 상담/첨부/잠금/인증 API와 메모리 PGlite를 사용했다. 문의 왕복, 답변/메모와 멘션 분리, 업로드·메시지 응답 유실 후 직접 재시도, 전송 중 다른 문의 선택, 권한 회수, 첨부 한도, 작성 잠금 재획득, 조직 전환과 로그아웃 경합·실패·늦은 인증 응답을 확인했다. 저장 후 503 시나리오는 업로드 1회·메시지 요청 2회·SQL 메시지 1건으로 중복 방지를 확인했다.

고객 위젯의 공용 첨부 훅 회귀 17개는 실제 `ChatWidget`·messenger API와 메모리 PGlite를 사용했다. 기존/새 문의의 첨부 초안, 첫 전송에만 문의 생성, 이미지 미리보기와 PDF/PNG 다운로드 4개의 원본 해시, 실제 iframe의 계정 A→B→A 전환 시 파일·문장 초기화와 추가 전송 없음, 모바일 표시를 확인했다.

직원 초안 저장소·전환 큐 단위 12개와 실제 SessionProvider 콜백을 실행한 합성 호스트 경합 9개도 통과했다. 콜백 호스트 검사는 React 렌더링·쿠키 저장소 검사가 아니며 위 실제 UI 검수와 구분한다.

통합 브랜치에서 전체 단위 1,133개(저장소/큐 12개 포함), 전체 TypeScript·변경 파일 lint, 첨부/감사 SQL/API 18개·답변 잠금 SQL/API 20개와 전체 Next.js webpack 프로덕션 빌드를 통과했다. 설치된 의존성만 junction으로 재사용하고 실제 환경 변수 파일을 읽지 않았으며 HTTP·TCP·TLS·DNS 호출을 차단했다. 이 빌드 결과는 배포하지 않았다.

전체 WorkspaceLayout/프로덕션 라우터, 네이티브 Windows Explorer의 수동 조작, 실제 조직 생성 API, AI 출처·이메일 수신자 조합, 실제 직원/고객 계정·부하·대용량 업무는 이번 UI 검수에 포함하지 않는다. 조직 생성 화면은 기존 가상 조직으로 쿠키를 바꾸는 시험 API를 사용했다. 실제 고객 DB·외부 서비스·R2·서버 배포는 사용하지 않았다.

이 변경은 별도 `codex/sendb-staff-drafts` 브랜치의 검토 대상이다. 채널톡 전체 자료 이전·두 사이트 설치·현업 전환 검수 및 R16은 계속 미완료다.
