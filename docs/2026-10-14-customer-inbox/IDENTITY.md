# 비회원 상담 → 회원 이력 연결

## 실제 사용 흐름

고객이 로그인 전 상담을 시작하고 사이트에 로그인하면, 사이트의 로그인 완료 처리에서 현재 비회원 상담을 회원 이력에 연결할 수 있다. 브라우저 SDK 1.1.0과 자체 상담 UI 모두 같은 공개 API를 사용한다. 아무 설정 없이 과거 브라우저 세션을 자동 수집하지 않는다.

```js
// 사이트 서버가 실제 로그인 세션을 검증해 발급한 15분 회원 JWT
const { data } = await (await fetch('/api/chat-identity', { method: 'POST' })).json();
await SendbChat.identify(data.identityToken, {
    mergeAnonymous: true,
    getIdentityToken: refreshVerifiedIdentity,
});
```

`mergeAnonymous: true`는 현재 SDK가 비회원으로 연결된 상태에서만 허용한다. A 회원 → B 회원 전환은 일반 `identify(token)` 또는 `shutdown()` 후 새로 연결한다. `boot()`와 일반 회원 인증 갱신은 비회원 이력을 합치지 않는다. 로그아웃 시 `shutdown()`을 호출하면 저장된 익명 증명이 지워진다. 공용 기기에서 다른 사람의 비회원 문의를 연결하지 않도록 실제 로그인 완료 흐름에서만 이 옵션을 사용한다.

자체 상담창은 다음 계약을 사용한다. 서비스 API 키를 넣지 않고, 서버가 확인한 회원 JWT와 해당 상담창의 비회원 세션 증명을 함께 제출한다. 익명 증명을 URL·로그에 넣지 않는다.

```http
POST /api/messenger/{channelKey}
Authorization: Bearer <memberIdentityToken>
Content-Type: application/json

{"action":"identify","anonymousToken":"<현재 비회원 세션 토큰>"}
```

응답은 `{success:true,data:{id,linked:true,merged:boolean}}`. 같은 회원의 재시도는 같은 상담 ID를 반환하고 다시 이동하거나 이벤트를 만들지 않는다. 다른 회원에게 이미 연결된 토큰은 409, 잘못된 증명·사업은 401이다. 고객이 입력한 이메일·고객 ID·이름으로 회원을 추정하지 않는다.

## 이력과 자동 처리

- 회원 상담이 없으면 기존 비회원 대화 자체를 회원에게 연결한다. 기존 상담이 있으면 메시지 ID·작성 시각·내용을 보존해 기존 상담으로 이동한다. 원래 상담 ID와 메시지 원본 ID를 보존하고 원본 상담을 삭제하지 않는다. 직원이 원래 상담 링크를 열면 연결된 상담을 조회하며 쓰기는 현재 상담에서만 가능하다.
- 보낸 첨부와 내부 메모는 메시지를 따라간다. 메모·메모 첨부는 회원 응답·CRM 공개 활동에서 계속 제외한다. 이전 감사 이력은 연결된 상담에서 함께 조회한다. 웹훅 원본 이벤트를 다시 쓰지 않고 `conversation.identified`로 원본/대상 상담과 고객 연결을 알린다.
- 태그를 합치고 중요 표시를 유지한다. 기존 회원 담당자가 있으면 유지하며 없으면 비회원 담당자를 사용한다. 고객 이름·연락처·CRM 연결은 서버가 확인한 회원 정보를 사용한다. 합산 태그 10개 초과나 메시지 번호 충돌은 409로 전체 연결을 보류하며 일부 이동하지 않는다.
- 이전 익명 토큰은 조회·전송·파일 접근에서 사용할 수 없다. 고객이 나중에 삭제되어 FK가 해제되어도 `identified_at`으로 익명 접근이 되살아나지 않게 한다. 전달 전에 인증한 요청도 메시지/파일 저장 시 다시 확인한다.
- 두 상담의 준비 중 AI와 대화 기반 예약·실패 자동화를 중단하고 사람 응대로 전환한다. 연결 전 맥락으로 늦게 자동 답변하는 것을 막는다. 이미 실행한 업무와 원본 실행 기록은 보존한다. 상담원이 확인 후 AI를 다시 허용할 수 있다. 종료된 과거 AI 작업은 원래 상담 ID로 DB에 보존하며 통합된 AI 작업 목록의 과거 원본 조회는 후속 확장이다.
- 합쳐진 공개 메시지는 원래 시각으로 공통 CRM 타임라인에 한 번만 기록한다. 받은 메시지는 보수적으로 미확인 상태에 포함한다. 단순 이력 이동으로 `message.created`를 재발행하거나 기존 고객에게 메시지를 전송하지 않는다.
- SDK 로그인 연결 중 작성 문장은 유지한다. 미전송 첨부는 취소하고 다시 선택하도록 안내한다. 서버 연결 실패 시 비회원 증명을 유지해 재시도할 수 있다. 탭을 닫거나 로그아웃한 후의 미전송 초안 복구는 별도 기능이다.

## 참고 근거와 선택

[Chatwoot 공식 병합 계약](https://developers.chatwoot.com/api-reference/contacts/merge-contacts)은 기존 고객으로 대화·라벨·속성을 옮기는 모델을 설명한다. 샌드비는 이를 그대로 복사하지 않고, 서버가 확인한 회원과 현재 비회원 증명에 한정해 연결하며 원본 상담을 보존한다. [Intercom 회원 식별 문서](https://developers.intercom.com/installing-intercom/web/identity-verification)와 기존 SDK REA 근거의 인증 경계를 유지한다. 이는 각 SaaS 내부 DB를 관찰했다는 뜻이 아니다.

## 검증과 남은 검수

마이그레이션 `0096_inbox_identity_link.sql`과 `scripts/check-inbox-identity.cjs`를 추가했다. 격리 PostgreSQL/PGlite에서 연결 API 12개: 이메일 비매칭, 인증/사업 범위, 메시지·첨부·메모/감사, 중복 집계 제외, AI/예약 취소, 멱등·계정 전환, 신규 회원 연결, 고객 삭제 후 익명 부활 차단, 충돌과 저장 실패 롤백, 두 사업/기기 복원을 확인했다. 기본 플랫폼 API 11개도 같은 실행에서 검사한다.

두 가상 사이트에서 비회원 문의 → 로그인 연결 → 위젯/자체 화면 이력 → 계정 전환/복원을 직접 클릭해 확인했다. 디하에서는 로그인 중 문장 초안 유지도 확인했다. 로컬 예제 로그인만 가상이며 실제 API·SDK·UI를 사용한다. 운영 DB·실제 고객·메일·Google Chat 전송은 사용하지 않았다.

실제 사이트의 로그인/로그아웃 연결, 다중 기기 동시 요청과 대규모 이력 이동의 부하·잠금 시간, 원본별 AI 작업 통합 표시, 기존 서비스 데이터 이전과 실제 업무 검수는 남아 있다. 임의 고객 간 CRM 병합·회원 간 병합은 이 API의 대상이 아니다.
