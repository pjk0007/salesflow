# 병합 전 상담의 AI 생성 기록

## 사용하는 방법

비회원 문의를 기존 회원 상담에 연결한 뒤 현재 상담의 **AI 답변 도우미**를 연다. 목록의 **현재 상담 기록**과 **병합 전 상담 기록**을 날짜·시각·초로 구분한다. 기록을 선택하면 당시 답변·사유·근거·모델 호출 사용량과 원본 생성 시각을 읽는다. **원본 상담 확인 정보**에서 원래 상담 ID를 확인한다.

병합 전 기록은 확인용이다. 과거 상태가 `ready`여도 답변에 넣기·생성 취소 버튼을 표시하지 않으며 API에서도 사용·전송·취소·원본 상담의 새 생성을 거절한다. **현재 상담 작업 → 현재 상담 초안 생성**은 지금 대화와 승인 지식으로 새 초안을 만드는 동작이다. 현재 초안의 삽입·사람 확인 후 전송 흐름은 유지한다.

목록·상세의 출처가 다르거나 출처를 확인할 수 없으면 화면의 사용·취소를 허용하지 않는다. 상세 조회 실패 시 선택과 작성 문장을 유지하고 **다시 불러오기**로 복구한다. 고객용 위젯/SDK 응답에는 직원 AI 기록·호출 사용량을 추가하지 않는다.

## API 계약

기존 native `/api/inbox/conversations/{id}/ai` 및 service `/api/v1/inbox/conversations/{id}/ai` GET과 상세 `/{runId}` GET을 확장한다. 서버 SDK `supportDrafts`·`supportDraft`도 같은 응답을 쓴다. 현재 상담과 **직접 병합된 원본**만 포함하며 조직·채널·사업을 확인한다. 원본 고객 ID는 익명인 null 또는 현재와 같은 회원이어야 한다. 다른 회원의 잘못된 병합 포인터로 이력을 포함하지 않는다.

요약과 상세 `job`에 다음 필드를 추가한다.

```ts
originConversationId: string; // AI 작업을 생성한 원래 상담 ID
fromMergedConversation: boolean; // 요청한 현재 상담의 병합 전 원본인지
```

조회 때문에 원본 작업 ID·conversationId·createdAt·상태·호출 이력을 재작성하지 않는다. createdAt/작업 UUID 내림차순으로 50개씩 읽고 마지막 작업 ID를 `before`로 전달한다. 커서도 같은 조회 범위 안에 있어야 한다. 과거 작업의 상세는 `usable=false`다.

취소는 현재 상담에 속한 대기/생성/준비 작업만 가능하다. UPDATE 조건에서 병합 원본을 직접 제외하므로 원본 주소의 과거 `ready` 취소도 409다. 현재 상담 주소로 다른 원본 작업을 전송/취소하는 기존 조건도 유지한다. 새 DB 테이블·마이그레이션·자동 워커는 추가하지 않는다.

## 검증

- 실제 익명→회원 병합, SDK·native/service API와 메모리 PGlite의 새 10개 및 공통 플랫폼 11개 검사 통과. 현재/직접 병합 원본 2개의 작업 120개 중 119개가 동일 시각이어도 3페이지에서 누락·중복이 없다. 다른 회원·사업·조직/잘못된 workspace·커서 제외, 과거 job/호출 스냅샷 보존과 legacy `ready` 사용 불가를 확인했다.
- 원본 주소에서 legacy `ready` 취소가 가능하던 경계를 재현해 보완했다. 과거 작업의 대상/원본 경로 취소·전송·재생성을 거절하고 현재 ready 초안은 실제 SDK로 한 번 전송한 뒤 재사용을 거절한다.
- 동일 쿠키·API 키를 유지해도 직원 사업 권한 또는 토큰 읽기/사업 범위를 회수하면 목록·현재/과거 상세·커서 모두 403이다. 키 범위를 복원하면 동일 키로 다시 읽을 수 있다.
- 전체 단위 1,127개(출처/실제 초기 SSR 6개 포함), 전체 TypeScript, 변경 lint, 기존 AI SQL/API 16개·회원 연결 12개, 전체 Next.js webpack 빌드 통과. 일반 검사 로그에는 자체 실행 시점 SHA가 없다. 제품 파일의 최종 편집 시각이 검사 시작보다 앞서고, 동결 API/타입 해시와 실제 UI 로드 소스 281개의 해시가 최종 코드와 일치하는 것으로 연결했다.
- Chrome의 실제 `SupportDraftPanel`·훅·native API/메모리 PGlite와 작은 React 호스트로 디하/백오랩 12개 화면 검수 통과. 현재 초안 삽입, 과거 ready의 읽기 전용/원본 ID·시각, 잘못된 사용 가능 응답에서도 버튼 차단, 503 표시/명시 재시도·선택 보존, 390px 가로 넘침 없음과 임시 viewport 복원을 확인했다. 호스트 삽입 콜백은 사업별 1회, 제품 API 변경 요청은 0건이다. 실제 전송·취소는 별도 SDK/API 검사가 증명한다.

증거·해시·명령은 `evidence-manifest.json`의 `mergedAiHistoryQa`에 있다. 소유 검수 탭·3148 서버·메모리 DB를 종료했고 실제 고객·모델·외부 서비스·서버 배포를 사용하지 않았다. 잘못된 응답은 명시적인 fixture 조건이며 제품 API의 실제 응답이라는 뜻이 아니다.

## 남은 범위

이번 화면 검수는 전체 InboxPage/WorkspaceLayout/Next 라우터·실제 사이트/Firebase 연결이 아니다. 두 화면은 작은 15개 기록이며 120개/3페이지 경계는 별도 SQL/API 검증이다. 실제 모델 품질·운영 부하와 전체 대체 전환 R16은 남는다. 비정상 legacy 작업의 모든 워커 상태를 동결하거나 임의 고객/회원 간 병합하는 기능은 추가하지 않는다. 현재 제품의 회원 연결 경로가 만드는 직접 병합 관계만 지원한다.

별도 `codex/sendb-merged-ai-history` 브랜치에서 검토한다. dev·main 병합이나 운영·개발 서버/실제 DB 반영은 수행하지 않았다.
