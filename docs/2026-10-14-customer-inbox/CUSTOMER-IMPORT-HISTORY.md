# 확인된 고객 본인의 과거 채널톡 상담

2026-10-15 · 사용자가 선택한 정책은 **확인된 고객 본인과 직원의 열람**이다. `codex/sendb-customer-import-history`의 로컬 개발 변경이며 실제 원본 계정 조회·고객 자료 이전·서버 반영은 수행하지 않았다. 기존 [고객 문의](CUSTOMER-HISTORY.md)와 [자료 이전](IMPORTS.md)의 후속 정책이다.

## 관리자 확인과 사용법

1. **기존 자료 이전**에서 대상 사업, 채널톡 원본 계정 이름(`namespace`), JSON 원본을 확인한다. 원본 계정의 `memberId`가 이 사업 사이트에서 서버 인증으로 확인하는 회원 `externalId`와 같은 체계인지 실제 연결 기준으로 확인한다. 이름·이메일 일치나 임의로 같은 ID를 붙인 자료는 본인 확인 근거가 아니다.
2. 이 관계를 확인한 경우에만 **확인된 회원 ID 기준 과거 상담 공개 확인**을 선택하고 새 미리보기를 만든다. API 입력 `verifiedCustomerHistory`는 기본 `false`다. 사업·원본 계정·원본 내용 등의 변경은 화면의 확인 선택을 해제한다.
3. 고객·상담 연결, 오류와 저장될 공개 선택을 검토한 뒤 가져오기를 실행한다. 서버는 승인된 원본 고객과 상담의 작업·결과·지문, 사업·채널·namespace 및 확인된 회원 ID를 함께 대조한다. 원본 회원 종류가 불명확하거나 익명 `veilId`인 자료는 공개 대상이 아니다.
4. 기존 미승인 작업은 직원 전용으로 남는다. 공개하려면 원본을 불러와 관계를 확인하고 새 미리보기로 재이전한다. 채널톡 JSON 외 형식과 CSV는 이번 고객 공개 대상이 아니다. 파일 원본 보충만으로 공개 승인이 생기지는 않는다.

이 선택은 관리자의 원본 계정·회원 체계 확인을 기록한다. 도구가 실제 원본 계정과 사이트의 동일성을 외부 조회로 자동 증명하는 기능은 아니다.

## 고객과 직원의 화면

- 확인된 고객은 **내 문의 목록**에서 자기 공개 과거 대화를 **이전 상담 · 읽기 전용**으로 구분해 읽는다. 원래 날짜·시간을 표시하며 현재 기본 문의나 안 읽은 답변 수에 포함하지 않는다. 직원은 기존 **이전 상담 기록**에서 권한에 맞게 확인한다.
- 고객에게는 공개 메시지와 현재 유효한 공개 첨부만 제공한다. 내부 메모·메모 첨부·다른 고객/사업의 기록은 제외하고, 첨부 다운로드 때도 소유 관계와 공개 승인을 확인한다. 원본 파일이 확보되지 않은 항목은 다운로드 완료로 표시하지 않는다.
- 과거 상담에 답장하거나 상담을 재개하지 않는다. 상태·담당 변경, 새 첨부, AI 생성도 제한한다. 후속 질문은 **새 문의로 상담 시작하기**에서 직접 작성·전송한다. 화면을 열기만 해서는 새 문의가 저장되지 않는다.
- 현재 문의와 새 문의의 문장·선택 파일은 같은 상담창에서 과거 기록을 왕복해도 보존한다. 과거 기록을 보는 동안 사이트의 `setDraft()`가 도착하면 새 문의용 문구로 보관하고 **새 문의 초안 열기**로 확인한다. 이미 작성한 새 문의 문장을 자동으로 덮거나 자동 전송하지 않는다. 계정/채널 변경·종료 뒤까지 영구 보관하는 기능은 아니다.

## API·인증·회수의 범위

목록 행과 상세의 `historyOnly`·`readOnly`로 읽기 전용을 구분한다. 기본 문의를 조회하는 ID 없는 요청은 현재 웹 문의를 사용하며 과거 상담을 현재 문의로 바꾸지 않는다. 위젯은 과거 상담에 읽음 요청을 보내지 않는다. 구 클라이언트가 공개 메시지의 읽음 확인을 보내도 서버는 `readRevision:0, unread:0`으로 응답하고 읽음 행을 저장하지 않는다.

회원 JWT의 유효기간은 15분이다. 로그아웃의 SDK `shutdown()`은 해당 창의 연결·상태를 정리하지만 이미 발급한 JWT를 서버에서 즉시 폐기하는 계약은 아니다. 로그인 변경 때는 사이트의 인증 연결과 SDK 종료/재연결 절차를 함께 지켜야 한다.

공개 승인·관계가 철회되면 같은 JWT라도 다음 목록·상세·첨부 조회에서 현재 조건을 다시 검사한다. 선택한 상세의 접근 거절은 내용을 숨기고 해당 목록 행을 무효화한다. 아직 다시 조회하지 않은 이전 목록 페이지의 캐시까지 실시간으로 모두 회수하는 기능은 아니다.
