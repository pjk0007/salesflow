# 상담 AI · 승인 지식과 사람 이관

직원/API 키 권한은 [사업별 역할 기준](ACCESS.md)을 따른다. 이 문서의 설정 관리자는 해당 사업의 운영 관리 역할 또는 조직 관리자이며, 일반 직원은 배정받은 사업 역할에 맞는 업무를 사용한다.

R09의 첫 구현이다. 기존 F08의 승인 지식을 상담에도 사용하고, 사업별 설정으로 수동 초안·자동 초안·자동 답변을 선택한다. 코드와 격리 QA는 dev에서 검토하며 실제 모델의 응답 품질과 운영 부하는 아직 검수하지 않았다.

## 사용하는 순서

1. 고객 상담 → **사이트 상담창 → 상담 AI·승인 지식 설정**, 또는 대화의 **AI 답변 도우미 → 지식·자동 응대 설정**을 연다. 사업 선택을 유지하며 별도 탭으로 열어 작성 중인 답변을 보존한다.
2. **새 지식 버전**에서 서비스 안내·FAQ·가격 등 확인한 사실, 근거 URL, 확인일을 등록하고 **고객 상담**을 선택한다. 초안을 검토해 **근거 확인 후 승인**한다. 수정할 때는 기존 버전을 복사한다.
3. 사용할 승인 지식, 모델, 말투 지침, 이관 담당자·안내 문구, 하루 생성 시도 한도를 정하고 **설정 검토 후 적용**한다. 기본은 수동 초안이다. 다른 사람이 먼저 변경했으면 작성한 설정을 보존하고 최신 설정을 불러오도록 안내한다.
4. 수동 모드는 대화의 **초안 생성 → 사용한 근거 확인 → 답변 초안에 넣기 → 검토·편집 → 답변 전송** 순서다. 이미 작성한 문장이 있으면 뒤에 추가한다. 새로고침해도 답변과 AI 초안 연결을 보존한다.
5. 자동 초안은 새 문의에서 초안을 만들고 상담원 전송을 기다린다. 자동 답변은 두 단계 검토를 통과한 답변을 **AI 상담 도우미** 이름으로 보낸다. 실제 자동 실행에는 서버 워커 활성화도 필요하다.
6. 고객은 **상담원 연결 요청**으로 사람 응대를 요청할 수 있다. 작성 중인 질문·파일은 지우지 않는다. 상담원 직접 답변, 연결·처리 요청, 첨부 자료, 답변 근거 부족·모델 실패 시 자동 응대를 중단한다. 필요하면 상담원이 대화에서 **AI 자동 응대 재개 허용**을 선택한다.

자동 이관은 중요 상담으로 표시하고 미배정이면 설정한 활성 담당자를 배정한다. 이미 배정된 담당자는 유지한다. 상담원이 직접 답변한 경우에는 중요 표시·담당자를 임의 변경하지 않는다. 자동 답변 모드의 고정 이관 안내는 이관 전환당 한 번만 보낸다. 수동 초안의 실패는 도우미 패널에 표시하고 고객에게 자동 안내하지 않는다.

## 근거와 전송 조건

- F08 `ai_copy_knowledge_versions`를 그대로 사용한다. 같은 사업의 승인 버전 중 `customer_chat`으로 표시되고 확인일이 과거 90일 이내인 사실만 검색한다. 메일 전용 사실은 상담에서 제외한다. 공유 지식을 차단하면 해당 버전의 메일 작업·실험에도 영향을 준다.
- 최근 공개 대화 최대 12개, 각 1,500자와 최신 질문, 관련 근거 최대 6개를 모델에 전달한다. 내부 메모·첨부 바이트는 모델 입력에서 제외한다. 첨부 내용 판독은 사람이 한다.
- 생성 모델은 답변·확신·정확한 인용을 반환한다. 알 수 없는 근거 ID, 원문에 없는 인용, 근거 없는 수치/단위·주소를 거부한다. 별도 모델 호출로 모든 주장과 질문 해결 여부를 재검토한다. 확신 기준은 두 단계 모두 0.85 이상이다.
- 생성·전송 시점에 대화의 최신 공개 메시지, 설정 버전, 지식 승인·확인일·지문을 확인한다. 새 문의, 상담원 답변, 설정 변경, 차단·만료, 취소 뒤에는 이전 초안을 사용할 수 없다. 상담원이 연결을 해제하고 일반 답변으로 전환하는 선택지는 제공한다.
- AI 초안은 한 번만 소비하고 최종 메시지 ID를 기록한다. 공개 고객 DTO와 웹훅에 생성 문맥·초안·인용·내부 사유를 싣지 않는다. 실제 공개 답변은 기존 `message.created` 계약을 사용한다.
- 기계 검증과 모델 검토는 오답 가능성을 없애지 않는다. 실제 서비스 FAQ로 질문 누락·잘못된 설명·불필요한 이관·한국어 말투를 평가한 뒤 자동 답변을 적용해야 한다. 현재 QA의 모델 응답은 전부 가상이다.

## API와 서버 SDK

서비스 API 토큰의 기존 사업 범위를 적용한다. 설정/지식 변경은 현재 조직의 관리자 발급 토큰만 허용한다. native 화면은 동일한 직원 권한과 출처 확인을 사용한다.

| API | 동작 |
|---|---|
| `/api/v1/support-ai/settings?workspaceId=...` GET | 현재 설정, 최근 지식 100개와 연결 버전, 최근 설정 이력 100개, 모델 연결·워커 상태 |
| `/api/v1/support-ai/settings` POST | workspaceId와 설정 전체 저장. `version` 충돌 시 409. 승인·신선도·담당자·모델 연결 검사 |
| `/api/v1/support-ai/knowledge?workspaceId=...&before=...` GET | 지식 버전 50개씩 조회 |
| `/api/v1/support-ai/knowledge` POST | workspaceId/name/snapshot으로 기존 F08 지식 초안 생성 |
| `/api/v1/support-ai/knowledge/{id}` POST | workspaceId/action=`approve` 또는 `block`/reason |
| `/api/v1/inbox/conversations/{id}/ai` GET | 생성 이력 요약 50개씩 조회. `before=runId` 커서 |
| 위 경로 POST | `{clientId: UUID}`로 수동 초안 요청. 같은 질문·번호는 같은 작업. 최대 90초 요청 시간 |
| `/api/v1/inbox/conversations/{id}/ai/{runId}` GET | 상태·답변·인용·호출 사용량·현재 사용 가능 여부 |
| 위 경로 POST | `{action:"cancel"}`. 대기/생성/준비 상태만 취소 |
| 기존 대화 POST | `kind:"reply"`와 선택 `aiDraftId`로 초안 소비·전송. 메모에는 연결 불가 |
| 기존 대화 PATCH | `version`과 `aiState:"auto"|"human"`으로 사람 응대/자동 응대 재개 |

`SendbClient`에 `supportAiSettings`, `updateSupportAiSettings`, `supportKnowledge`, `createSupportKnowledge`, `reviewSupportKnowledge`, `supportDrafts`, `generateSupportDraft`, `supportDraft`, `cancelSupportDraft`를 추가했다. `reply`의 마지막 선택 인자는 `aiDraftId`다. 기존 호출 인자와 메일 목적은 유지한다.

`ai.draft.ready` 이벤트는 검토 통과 후 생성 상태/번호만, `ai.handoff`는 실제 사람 응대 전환과 담당/중요 표시만 outbox에 기록한다. 워커의 고정 이관 답변과 고객 요청 이관도 같은 원본 트랜잭션을 사용한다. 메모·상담 지식은 내보내지 않는다.

## 운영 설정과 한계

- 마이그레이션 `0094_customer_ai_support.sql`: 사업 설정/버전 이력, 생성 작업/호출/일별 시도, 대화 응대 상태, 메시지의 초안 연결. 기존 메일 승인 지식을 별도 테이블로 복제하지 않는다.
- 자동 워커는 `NODE_ENV=production` 및 `CUSTOMER_AI_WORKER=on`일 때만 실행한다. 기본 꺼짐. 기존 Anthropic/Gemini/DeepSeek 연결과 월별 공용 토큰 한도를 재사용한다. 사업별 하루 생성 시도는 기본 50, 설정 범위 1~1,000이다.
- 자동 작업은 마지막 문의에서 10초 뒤 처리한다. 새 공개 메시지는 이전 대기/생성/준비 작업을 무효화한다. 작업 lease는 90초, 생성 시도는 최대 두 번이다. 각 모델 단계는 25초 제한이며 공급자 내부 재시도는 끈다. 복구 한도 후에는 사람에게 넘긴다.
- 실제 응답의 사용량을 공용 집계에 증분 반영하며 늦은 응답도 중복 집계하지 않는다. 미확인 토큰은 호출 화면에서 ‘일부 확인 중’으로 표시한다. 월별 한도는 기존 사전 확인 방식이며 동시 작업에 대한 과금 예약·절대 지출 한도는 아니다.
- 한 워커가 한 번에 한 작업을 처리하는 초기 구현이다. 대규모 동시 상담, 다중 인스턴스의 실제 모델 지연·비용·복구 부하는 후속 검수다. 벡터 DB·URL 크롤링·PDF 검색·다국어·음성·외부 작업 실행은 포함하지 않는다.

## 검증

- 단위 1,047개, 상담 AI SQL/API 16개, 기존 상담 22개·플랫폼 11개·영업 13개·공통 활동 7개·첨부/감사 18개·웹훅 14개 통과. F08 관리 18개와 자동화 40개 호환 검사를 수행했다.
- 실제 route/auth/SDK/SQL로 수동·자동 초안/답변, 사람 이관/재개, 내부 메모 제외, 첨부, 근거 부족·환각 수치·검증 실패·공급자 실패, 새 문의/답변/설정/취소 경쟁, 지식 차단/만료, 사용량·일일 한도·타 사업 격리·현재 관리자 역할·lease 복구를 확인했다.
- Chrome에서 지식 복사→저장→승인→설정 적용, 디하 수동 생성→기존 문장 뒤에 삽입→근거 확인→새로고침 보존→전송·수신, 백오랩 자동 답변→고객의 사람 요청→질문 초안 보존→담당 배정·중요 표시·응대 중단을 직접 확인했다.
- 증거는 로컬 `artifacts/sendb-replacement-20261014/ai-*.png`와 `ai-*.log`에 보존한다. 가상 FAQ·고객·모델 응답·격리 DB만 사용했다. 실제 공급자 호출, 운영 DB 접근, 실제 고객·메일·Google Chat 발송, 운영 배포는 없다.

0110의 답변 잠금을 켠 사업에서 상담원이 작성 중이면 AI 워커가 결과를 ready 초안으로 보존하고 자동 전송/자동 재전송하지 않는다. 상담원이 근거와 최신 대화를 확인해 전송한다. 사람 이관 안내도 작성 중에는 공개 전송하지 않는다. 가상 모델과 독립 PostgreSQL의 실제 워커·사람 전송까지 추가 검수했다. [REPLY-GUARD.md](REPLY-GUARD.md) 참고.
