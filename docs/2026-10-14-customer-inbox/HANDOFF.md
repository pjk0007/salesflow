# 샌드비 고객 상담

- **직원 업무 UX 가이드**: [여섯 업무·28단계 오프라인 안내](UX-GUIDE.md). 실제 메뉴·완료 확인·복구·역할과 기능별 가상 검수 화면을 연결했습니다. 문서와 가이드 자체만 검수했으며 제품 전체 검사를 반복하거나 서버에 적용하지 않았습니다. 운영·설치·현업 인수 완료를 뜻하지 않습니다.

이 체크아웃은 `codex/sendb-development-review`의 로컬 조합 검토다. 추출기 `65f2d04`, 직원 초안 `d99746e`, D1 첨부 일괄 보충 `4646674`, D3 병합 전 AI 이력 `d2635b1`을 함께 적용했으며 개별 기능 PR과 아래 검증 근거는 보존한다. 네 기능의 조합 단위 1,274개·전체 타입·webpack 빌드가 통과했다([별도 조합 검수](DEVELOPMENT-COMBINATION.md)). 다른 브랜치·실제 서버/DB·외부 발송에는 반영하지 않는다.

샌드비 자체 고객 상담과 API 기반 고객 플랫폼의 첫 확장이다. 백오피스랩·디자이너하이어에서 설치할 수 있도록 서비스 서버 API, 회원 식별, 브라우저 SDK를 추가했다. 채널톡·인터컴·허브스팟의 SDK와 공개 구현체를 참고했으며 코드·로고·고객 데이터를 복사하지 않았다. 전체 대체 목표와 미완료 항목은 [REPLACEMENT.md](REPLACEMENT.md), 분석 근거는 [ANALYSIS.md](ANALYSIS.md), 설치 계약은 [API.md](API.md)에 있다.

추가 제공 리서치는 [RESEARCH-APPLIED.md](RESEARCH-APPLIED.md)에 원본 확인·반영·미확인을 구분했다. 상담 안에서 회사/거래를 보고 딜·후속 업무를 생성하며 같은 고객 타임라인에 남기는 흐름을 구현했다.

2026-10-15 확인한 현재 사용 채널은 **채널톡**이다. 이번 전환은 채널톡의 상담/자료와 두 웹사이트 연결을 필수로 검토한다. 이메일/Gmail·카카오·네이버·전화는 선택 확장으로 구분하고 기존 CRM·AI·자동화 범위는 유지한다. 실제 서버/운영·고객 데이터는 변경하지 않는다.

## 설치

1. 관리자가 고객 상담 → **사이트 상담창**에서 사업·이름·환영 인사·색상·설치 도메인을 저장한다. 워크스페이스마다 상담창 하나를 만든다.
2. 기본은 꺼짐이다. 설치할 도메인(예: `https://designer-hire.com`)을 등록하고 사용을 켠다. URL 경로가 아니라 출처를 넣는다. 다른 사업의 상담창은 별도로 만든다.
3. 화면의 설치 코드를 해당 사이트 HTML에 추가한다. 스크립트 경로는 배포한 샌드비 서버의 `/sendb-chat.js`, 상담창은 `/chat/{publicKey}`다. 채널톡 API 키나 구독이 필요 없다.
4. `dev`에서 생성한 설치 코드를 운영 사이트에 설치하지 않는다. 운영 반영과 사이트 설치는 검토 후 진행한다.

- 공개 키는 위젯 선택용이며 인증 비밀이 아니다. 익명 세션은 256비트 랜덤 토큰이며 DB에는 SHA-256만 저장한다. 회원은 별도 용도로 서명한 15분 JWT를 사용한다. 토큰을 URL에 싣지 않는다.

- 운영 DB 접근, 실제 고객 대화 발송, 운영 사이트 설치는 이번 작업에서 수행하지 않는다. 로컬 UI는 격리 PGlite 및 가상 고객으로 확인한다.
- 브랜치 `dev`, 검토 PR은 초안으로 유지한다. `main` 병합 및 운영 배포는 별도 요청 대상이다.
