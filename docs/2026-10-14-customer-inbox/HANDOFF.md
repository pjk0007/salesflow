# 샌드비 고객 상담

채널톡 외부 연동이 아니라 샌드비 자체에서 동작하는 고객 상담 기능이다. 사용자 요청에 따라 로그인된 채널웍스 수신함을 관찰하고 REA로 공개 배포 JS를 정적으로 분석했다. 채널톡 코드·로고·고객 데이터는 구현에 복사하지 않았다.

## 사용할 수 있는 기능

- 좌측 메뉴의 **고객 상담** (`/inbox`): 사업별 수신함, 진행중/보류중/종료됨, 미확인/내 상담/미배정/중요 필터, 이름·이메일·태그·최근 메시지 검색.
- 사이트 상담 위젯: 설치 스크립트 한 줄, 방문자 이름·선택 이메일 입력, 문의와 상담원 답변, 새로고침 후 세션 복구. 이메일 알림이 아니라 상담창에서 답변을 확인하는 방식이다.
- 상담원 답변과 내부 메모 분리. 내부 메모는 공개 API·방문자 화면·CRM 여정·상담 미리보기에서 제외한다.
- 조직의 활성 팀원 담당 지정, 태그, 중요 표시, 보류·종료·다시 열기. 고객의 재문의는 보류/종료 상담을 진행중으로 돌린다.
- 고객을 확인한 뒤 같은 워크스페이스 CRM 레코드를 수동 연결. CRM 여정에서 고객 문의·상담원 답변을 확인하고 상담 수신함으로 돌아갈 수 있다. 고객 입력 이메일로 다른 고객의 CRM 정보를 자동 공개하지 않는다.
- 사용자별 읽음 순번과 답변 초안 보존. 읽은 뒤 도착한 메시지를 미확인으로 유지한다. 메시지 clientId를 사용해 네트워크 재시도의 중복 저장을 막는다.
- 수신함 4초, 열린 대화/방문자 상담창 3초 간격 갱신. 100개씩 이전 상담/메시지 조회. 검색과 필터는 현재 불러온 상담을 대상으로 하며 화면에 범위를 표시한다.

## 설치

1. 관리자가 고객 상담 → **사이트 상담창**에서 사업·이름·환영 인사·색상·설치 도메인을 저장한다. 워크스페이스마다 상담창 하나를 만든다.
2. 기본은 꺼짐이다. 설치할 도메인(예: `https://designer-hire.com`)을 등록하고 사용을 켠다. URL 경로가 아니라 출처를 넣는다. 다른 사업의 상담창은 별도로 만든다.
3. 화면의 설치 코드를 해당 사이트 HTML에 추가한다. 스크립트 경로는 배포한 샌드비 서버의 `/sendb-chat.js`, 상담창은 `/chat/{publicKey}`다. 채널톡 API 키나 구독이 필요 없다.
4. `dev`에서 생성한 설치 코드를 운영 사이트에 설치하지 않는다. 운영 반영과 사이트 설치는 검토 후 진행한다.

## 데이터와 배포

- 마이그레이션 `0088_customer_inbox.sql`: `inbox_channels`, `inbox_conversations`, `inbox_messages`, `inbox_reads` 네 테이블만 추가한다. 기존 메일/트래커 데이터를 변경하지 않는다.
- 공개 키는 위젯 선택용이며 인증 비밀이 아니다. 상담 세션은 256비트 랜덤 토큰이며 DB에는 SHA-256만 저장한다. 토큰을 URL에 싣지 않는다.
- 고객 문의 페이지는 허용 도메인에서 온 경로만 저장하고 query/hash를 제거한다. 메시지는 HTML로 실행하지 않는다.
- 공개 API의 IP 제한은 기존 단일 인스턴스 메모리 limiter를 재사용한다. 세션별 메시지 제한은 DB 잠금 안에서 분당 20개이며 다중 인스턴스에서도 적용된다.
- 운영 DB 접근, 실제 고객 대화 발송, 운영 사이트 설치는 이번 작업에서 수행하지 않는다. 로컬 UI는 격리 PGlite 및 가상 고객으로 확인한다.
- 브랜치 `dev`, 검토 PR은 초안으로 유지한다. `main` 병합 및 운영 배포는 별도 요청 대상이다.

## 검증

`node --import tsx scripts/check-inbox.cjs`: 마이그레이션/스키마 일치, 송수신, 내부 메모 비공개, 읽음 경쟁, 중복 제출, 재문의 재개, 조직·채널 격리, 담당자·CRM 연결, 세션 복구, 입력·도메인 검사, 제한, 비활성화, 동일 시각 100건 초과 페이지 경계를 격리 SQL로 검사한다. 기존 검사와 같은 `.testenv/test-runtime` PGlite가 필요하다.

브라우저 QA는 실제 `/sendb-chat.js`를 설치한 로컬 가상 사이트에서 문의 → 수신함 답변 → 방문자 수신 → 내부 메모 비공개 → 종료 후 재문의를 직접 클릭해 확인한다. 테스트 더블은 DB/인증만 대체하고 실제 API와 UI를 사용한다.

## REA 관찰 근거와 한계

- 관찰 화면: 사용자가 지정한 `channel.works/designerhire/user-chats/...`의 수신함, 대화, 고객 정보, 담당자, 내부대화, 상태 및 설정 미리보기.
- 공개 배포 버전 `49.31.0`의 `useSendMethodToggle` JS를 REA 6.4.0 CLI로 정적 분석. Evidence `ev_925022207d38495167a5ee2e99ee67bb0a6daf0d9f865ed6dc86df6cb7293e01`.
- 정적 분석은 전송 키 설정 hook과 번들 모듈의 존재를 확인하는 근거다. 전체 서버 구현, 실제 실행 경로, 비공개 API의 동작을 증명하지 않는다. 샌드비에서는 자체 DB/API로 구현하며 Ctrl/⌘+Enter와 명시적 전송 버튼을 사용한다.

## 범위

이번 버전은 웹 텍스트 고객 상담의 핵심 흐름을 제공한다. 채널톡의 기존 대화 이전, 전화·음성 상담, 카카오/네이버 수신, 파일 첨부, ALF 자동 응대, 마케팅·워크플로 자동화, 푸시/이메일 알림, 상담 만족도 수집은 구현하지 않았다. 기존 채널톡과 병행할 경우 위젯 두 개가 겹치지 않도록 사이트 설치 시 확인한다.
