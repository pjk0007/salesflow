# 샌드비 고객 상담

샌드비 자체 고객 상담과 API 기반 고객 플랫폼의 첫 확장이다. 백오피스랩·디자이너하이어에서 설치할 수 있도록 서비스 서버 API, 회원 식별, 브라우저 SDK를 추가했다. 채널톡·인터컴·허브스팟의 SDK와 공개 구현체를 참고했으며 코드·로고·고객 데이터를 복사하지 않았다. 전체 대체 목표와 미완료 항목은 [REPLACEMENT.md](REPLACEMENT.md), 분석 근거는 [ANALYSIS.md](ANALYSIS.md), 설치 계약은 [API.md](API.md)에 있다.

추가 제공 리서치는 [RESEARCH-APPLIED.md](RESEARCH-APPLIED.md)에 원본 확인·반영·미확인을 구분했다. 상담 안에서 회사/거래를 보고 딜·후속 업무를 생성하며 같은 고객 타임라인에 남기는 흐름을 구현했다.

## 사용할 수 있는 기능

- **여러 참여자의 이메일 상담과 전체 회신**: 같은 메일함 스레드의 발신자별 원본, 최신 Reply-To/To/Cc 기준 답장/전체 회신/직접 지정, 새 메일 도착 시 초안 보존·대상 재확인, 고정 수신자 큐/재시도와 접수 이력을 제공합니다. SQL/API16·전체 단위1,089·기존 15개 회귀 검사·두 사업 Chrome QA. 발신 별칭·실제 계정/배달은 후속입니다. [이메일 회신 UX/API·0104](EMAIL-RECIPIENTS.md) 참고.

- **고객·회사 변경 이력과 보관**: 타입을 구분한 추가 속성 편집, 수정자/출처/필드별 전후 값·버전 검사, 보관 전 상담·거래·업무 영향 확인, 대기 자동화 중단·보관함·복구와 API/SDK. 상담/회원/메일/파일·기존 관계를 보존하며 복구해도 옛 자동화는 재개하지 않습니다. SQL/API19·전체 단위1,085·기존 14개 회귀 검사·두 사업 Chrome QA. 마이그레이션 0103, 실제 DB 적용/영구 파기·보존 기간 정책은 후속입니다. [고객 정보 UX/API 가이드](CUSTOMER-RECORDS.md) 참고.

- **직원 사업 권한**: 조직 관리자가 사업별 열람·응대/편집·운영 관리 배정/회수와 변경 이력을 관리합니다. 상담·CRM·메일함·AI·자동화·연동·이전·성과의 직원/API 키 권한을 통일하고 현재 역할/세션/활성 상태를 확인합니다. 새 일반 직원 기본 접근 없음, 실제 팀 배정은 미수행. SQL/API18·단위1,075·두 사업 Chrome QA. [권한 UX/API·배포 검토](ACCESS.md) 참고.


- **상담 운영·성과**: 개인 알림→사업별 상담, 업무시간/휴무일·고객 안내, 첫/추가/해결 목표와 보류 시간 제외·고정 설정, 일별/담당자/미응답/표본 보고서·API/SDK. SQL/API23·달력8·두 사업 Chrome QA, 초과 워커 기본 꺼짐. [운영 UX/API 가이드](OPERATIONS.md) 참고.


- **Gmail 계정 연결·자동 수신**: 사업별 OAuth/수신 범위·수신 발송 허용, 영속 원본 대기열/history·첨부/답장 처리·실패 재요청/계정 재연결. SQL/API 19개와 두 사업 가상 UI QA. 자동 워커 기본 꺼짐이며 실제 계정/서버 설정은 미설치. [연결·복구 가이드](GOOGLE-CONNECTION.md) 참고.


- **기존 고객 자료 이전** (`/customer-imports`): 세 서비스 JSON/CSV·원본 ID/관계 매핑·무변경 미리보기·사람 실행·25행 묶음/복구·중복/수정 보호. 과거 상담은 별도 필터·원본 시각/내부 메모·CRM 연결로 확인하며 발송하지 않는다. [이전 UX/API 가이드](IMPORTS.md) 참고.

- **비회원 → 회원 상담 연결**: 로그인 완료 시 현재 비회원 증명과 서버 회원 JWT로 이력을 연결한다. 기존 회원 대화와 메시지·첨부·메모/감사·CRM 활동을 이어주고 옛 익명 증명·이전 예약/AI 처리를 중단한다. SDK 1.1.0·자체 API 예제와 [회원 연결 가이드](IDENTITY.md) 참고.

- **고객 자동화** (`/customer-workflows`): 이벤트/조건→단계·예약·행동, 모의 실행→사람 게시, 고정 버전·멱등/롤백·중단/재시도·실행 이력. 고객 관리와 상담창 설정에서 열 수 있다. 자동 워커 기본 꺼짐. [자동화 UX/API 가이드](WORKFLOWS.md) 참고.

- **상담 AI와 승인 지식** (`/customer-ai`): F08 지식 재사용·상담 목적/승인, 수동/자동 초안과 선택 자동 답변, 인용/질문 해결 검토, 사람 이관/재개·담당 배정·실패/사용량 이력. 자동 워커 기본 꺼짐. [상담 AI 가이드](AI-SUPPORT.md) 참고.

- **고객 관리** (`/customer-crm`): 고객·회사 편집/관계·행동 이력, 사업별 파이프라인, 딜 보드·단계 감사·보관/복원, 담당자의 다음 할 일·완료/재개/취소. 동시 편집 충돌과 최신 내용 불러오기. [영업 흐름 가이드](SALES.md) 참고.
- 회원 상담의 **고객과 영업** 패널: 연결 회사·진행 거래·예정 업무 조회, 상담 중 딜/후속 업무 생성과 완료, 공통 고객 타임라인. 타임라인은 10초 간격 갱신하며 내부 메모는 포함하지 않는다.
- 좌측 메뉴의 **고객 상담** (`/inbox`): 사업별 수신함, 진행중/보류중/종료됨, 미확인/내 상담/미배정/중요 필터, 이름·이메일·태그·과거 메시지를 포함한 서버 전체 검색과 전체 결과 집계.
- 사이트 상담 위젯: 설치 스크립트 한 줄, 방문자 이름·선택 이메일 입력, 문의와 상담원 답변, 새로고침 후 세션 복구. 이메일 알림이 아니라 상담창에서 답변을 확인하는 방식이다.
- 고객·상담원·내부 메모 파일 첨부, 파일만 전송, 보호된 다운로드·이미지 미리보기. 담당/상태/태그/CRM 연결·설정 감사와 동시 편집 충돌 처리. [파일·변경 이력 가이드](FILES-AUDIT.md) 참고.
- 상담원 답변과 내부 메모 분리. 내부 메모는 공개 API·방문자 화면·CRM 여정·상담 미리보기에서 제외한다.
- 해당 사업의 현재 응대 가능한 활성 팀원 담당 지정, 태그, 중요 표시, 보류·종료·다시 열기. 고객의 재문의는 보류/종료 상담을 진행중으로 돌린다.
- 고객을 확인한 뒤 같은 워크스페이스 CRM 레코드를 수동 연결. CRM 여정에서 고객 문의·상담원 답변을 확인하고 상담 수신함으로 돌아갈 수 있다. 고객 입력 이메일로 다른 고객의 CRM 정보를 자동 공개하지 않는다.
- 사용자별 읽음 순번과 답변 초안 보존. 읽은 뒤 도착한 메시지를 미확인으로 유지한다. 메시지 clientId를 사용해 네트워크 재시도의 중복 저장을 막는다.
- 수신함 4초, 열린 대화/방문자 상담창 3초, 닫힌 위젯 최대 15초 간격 갱신. 100개씩 이전 상담/메시지 조회. 상태·필터·검색을 바꾸면 해당 조건의 커서로 시작한다.
- 서비스 API 토큰의 워크스페이스 범위로 고객·회사·관계·행동 이벤트·상담을 연결한다. 같은 외부 회원 ID도 사업별로 구분한다.
- 사이트 서버가 확인한 회원에 짧은 서명 인증을 발급한다. 회원은 입력 폼 없이 문의하고 다른 기기에서도 같은 이력을 이어간다. 인증 갱신은 초안을 유지하며, 계정 전환/로그아웃은 SDK shutdown으로 이전 인증을 제거한다.

- **고객 플랫폼 외부 연동** (`/customer-webhooks`): 사업별 웹훅 구독·서명 키 발급·활성화, 원본/시도/실패/수동 재시도. 고객 관리에서 현재 사업을 유지해 열 수 있다. [웹훅 가이드](WEBHOOKS.md) 참고.

## 설치

1. 관리자가 고객 상담 → **사이트 상담창**에서 사업·이름·환영 인사·색상·설치 도메인을 저장한다. 워크스페이스마다 상담창 하나를 만든다.
2. 기본은 꺼짐이다. 설치할 도메인(예: `https://designer-hire.com`)을 등록하고 사용을 켠다. URL 경로가 아니라 출처를 넣는다. 다른 사업의 상담창은 별도로 만든다.
3. 화면의 설치 코드를 해당 사이트 HTML에 추가한다. 스크립트 경로는 배포한 샌드비 서버의 `/sendb-chat.js`, 상담창은 `/chat/{publicKey}`다. 채널톡 API 키나 구독이 필요 없다.
4. `dev`에서 생성한 설치 코드를 운영 사이트에 설치하지 않는다. 운영 반영과 사이트 설치는 검토 후 진행한다.

## 데이터와 배포

- 마이그레이션 `0088_customer_inbox.sql`의 상담, `0089_customer_platform.sql`의 고객·회사·관계·이벤트와 상담 contact_id, `0090_customer_sales.sql`의 파이프라인·딜·딜 이력·할 일 테이블을 추가한다. 기존 메일/트래커 데이터를 수정하는 마이그레이션은 없다.
- `0091_customer_activities.sql`: 공통 활동 테이블과 확인 가능한 기존 이벤트·딜 감사·공개 상담 복원. 기존 업무는 과거 변경을 추정하지 않고 현재 상태 스냅샷만 남긴다. 원본 저장과 같은 트랜잭션에 새 활동을 기록한다.
- `0092_inbox_files_audit.sql`: 상담 version·첨부 메타데이터·비공개 bytea 원본·감사 테이블. 각 20MiB/5개, 기본 사업별 2GiB. 실제 전환 전 DB/백업 용량·부하 검수가 필요하다.
- `0093_platform_webhooks.sql`: 공통 이벤트·웹훅 설정/전달/시도/감사. 원본과 같은 트랜잭션에서 이벤트를 기록한다. 자동 전송은 기본 꺼짐이며 서버 CUSTOMER_WEBHOOK_WORKER=on 설정과 수신 설정 활성화가 모두 필요하다.
- `0094_customer_ai_support.sql`: 상담 AI 설정/버전 이력·작업/호출/일별 시도·대화 응대 상태·메시지 초안 연결. 자동 실행은 CUSTOMER_AI_WORKER=on과 사업별 자동 모드가 필요하다. 실제 모델 QA 후 적용한다.
- `0095_customer_workflows.sql`: 자동화/이름·설명·정의 버전/모의 실행/실행·단계·감사와 이벤트 원인 실행 번호. CUSTOMER_WORKFLOW_WORKER=on과 사람이 검토한 사업별 게시가 모두 필요하다.
- `0096_inbox_identity_link.sql`: 상담 원본/연결 대상·회원 확인 시각·메시지 원본 상담 ID를 추가한다. 비회원 이력 연결은 명시적인 로그인 완료 호출에서만 실행한다.
- `0097_customer_imports.sql`: 원본/검토 작업·원본 ID 연결·행별 전후 결과·감사와 과거 상담/메시지 원본 정보를 추가한다. 이 마이그레이션에서 회원 상담의 유일성은 `history_only=false`에 적용하고 과거 상담은 여러 개 보관한다. 기존 메일 원본/발송 상태는 변경하지 않는다.
- 공개 키는 위젯 선택용이며 인증 비밀이 아니다. 익명 세션은 256비트 랜덤 토큰이며 DB에는 SHA-256만 저장한다. 회원은 별도 용도로 서명한 15분 JWT를 사용한다. 토큰을 URL에 싣지 않는다.
- 고객 문의 페이지는 허용 도메인에서 온 경로만 저장하고 query/hash를 제거한다. 메시지는 HTML로 실행하지 않는다.
- 공개 API의 IP 제한은 기존 단일 인스턴스 메모리 limiter를 재사용한다. 세션별 메시지 제한은 DB 잠금 안에서 분당 20개이며 다중 인스턴스에서도 적용된다.
- 운영 DB 접근, 실제 고객 대화 발송, 운영 사이트 설치는 이번 작업에서 수행하지 않는다. 로컬 UI는 격리 PGlite 및 가상 고객으로 확인한다.
- 브랜치 `dev`, 검토 PR은 초안으로 유지한다. `main` 병합 및 운영 배포는 별도 요청 대상이다.

## 검증

`node --import tsx scripts/check-inbox.cjs`: 마이그레이션/스키마 일치, 송수신, 내부 메모 비공개, 읽음 경쟁, 중복 제출, 재문의 재개, 조직·채널 격리, 담당자·CRM 연결, 세션 복구, 입력·도메인 검사, 제한, 비활성화, 동일 시각 100건 초과 페이지 경계를 격리 SQL로 검사한다. 기존 검사와 같은 `.testenv/test-runtime` PGlite가 필요하다.
