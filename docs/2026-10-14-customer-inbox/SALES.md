# 고객 관리 · 영업 흐름 가이드

직원/API 키 권한은 [사업별 역할 기준](ACCESS.md)을 따른다. 이 문서의 설정 관리자는 해당 사업의 운영 관리 역할 또는 조직 관리자이며, 일반 직원은 배정받은 사업 역할에 맞는 업무를 사용한다.

좌측 **고객 관리**(`/customer-crm`)에서 사업을 선택한다. 디자이너하이어와 백오피스랩의 고객·회사·파이프라인·딜·할 일은 별도로 저장된다. 기존 자유형 CRM 레코드와 메일·방문 여정 화면도 계속 사용한다.

## 처음 준비할 때

1. **회사**에서 거래할 회사를 등록한다. **고객**에서 이름·연락처·고객 단계·연결 회사를 정리한다. 여러 회사 관계를 선택할 수 있고, 내부 구성원도 별도로 표시한다.
2. 관리자가 **파이프라인**에서 사업의 영업 단계를 만든다. 기본 예시를 수정해 디하는 도입상담/제안, 백오피스랩은 업무 범위 확인/견적 제안 등으로 구성한다. 진행·성사·실패 구분과 순서도 설정한다.
3. **딜 추가**에서 고객·회사·담당자·금액·예상 계약일을 연결한다. 딜 제목을 눌러 단계와 내용을 바꾼다.
4. 딜 카드의 **다음 할 일 추가**를 누르면 해당 딜·고객·담당자가 연결된 업무를 만든다. 예정 시각과 업무 내용을 입력하고, 할 일 화면에서 완료·재개·취소한다.

업무를 등록했다고 고객에게 자동 연락하지 않는다. 공통 자동화와 상담 알림은 후속 기능이다. 외부 시스템 번호는 연동을 사용할 때만 펼쳐 입력한다. 생략하면 화면이 생성한 번호를 재시도 동안 유지해 중복 생성을 막는다.

## 확인할 때

- 딜 보드는 파이프라인 단계별로 표시한다. 제목을 열면 변경자·시각·단계와 보관/복원 이력이 나온다.
- 불필요한 딜은 **보관**하고, ‘보관된 딜’에서 다시 복원한다. 서버 대화·고객·업무 이력을 삭제하지 않는다.
- 고객을 열면 서버/사이트가 기록한 행동 이벤트를 확인한다. 사이트에서 회원 인증을 거쳐 기록한 이벤트가 해당 고객에 연결된다.
- 고객 타임라인은 공개 상담·고객 이벤트·딜·업무의 기록을 함께 보여준다. 회원 상담의 오른쪽 패널에서도 같은 기록을 읽고 딜·후속 업무를 생성한다. 내부 상담 메모는 제외한다.
- 회원 상담의 고객 정보에서 **고객 관리에서 딜·할 일 연결**로 이동하면 해당 사업의 고객 이름을 검색한다.
- 목록과 이력은 100개씩 불러온다. 표시 건수는 현재 불러온 범위이며 다음 항목/이전 기록 버튼으로 이어본다. 딜·할 일·고객·회사 이름 검색은 서버에서 수행한다.

## 같이 수정할 때

같은 딜·할 일·파이프라인을 다른 팀원이 먼저 저장하면 오래된 편집은 409로 거절한다. 화면은 작성 내용을 유지하고 **최신 내용 불러오기**를 제공한다. 이 버튼을 누르면 최신 값으로 폼을 교체하므로 새 내용을 확인한 뒤 저장한다. 사용 중인 단계는 삭제할 수 없으며 딜을 먼저 다른 단계로 옮긴다. 보관된 딜이 사용하는 단계도 보존한다.

고객·회사의 현재 편집은 외부 ID upsert 방식이다. 필드별 변경 이력·동시 편집 통제·보존/삭제 정책은 전체 고객 플랫폼의 후속 항목으로 남아 있다.

## API로 연결할 때

`/api/v1/crm/pipelines`, `/deals`, `/tasks`에서 GET 목록·POST 생성, `/{id}`에서 GET 상세·PATCH 수정을 제공한다. 읽기는 `workspaceId` 쿼리, 쓰기는 JSON `workspaceId`가 필요하며 서비스 토큰의 해당 사업 권한을 검사한다.

생성에는 `externalId`가 필수다. 같은 외부 번호·같은 내용의 재시도는 기존 항목을 반환하고 다른 내용이면 409다. 수정에는 조회한 `version`을 함께 보내며 성공하면 1 증가한다. 고객·회사·파이프라인·딜 관계는 같은 사업만 허용하고 담당자는 같은 조직의 활성 구성원이어야 한다.

```ts
const pipelines = await client.pipelines(workspaceId);
const deal = await client.createDeal({
    workspaceId, externalId: "website-contract-123", title: "디자인 구독 도입",
    pipelineId: pipelines[0].id, stageId: pipelines[0].stages[0].id,
    contactId, amount: "1500000", currency: "KRW",
});
const task = await client.createTask({
    workspaceId, externalId: "contract-123-next-action", title: "도입 일정 확인",
    dealId: deal.id, contactId, ownerId, dueAt: "2026-10-15T01:00:00Z",
});
await client.updateTask(task.id, { workspaceId, version: task.version, status: "done" });
```

금액은 소수 둘째 자리까지의 **문자열**로 전달한다. 날짜는 계약일 `YYYY-MM-DD`, 업무 예정 시각은 타임존을 포함한 ISO datetime이다. 목록은 UUID 내림차순 커서이며 마지막 id를 `before`로 넘긴다. 딜 변경 이력은 시각·ID 내림차순이고 마지막 이력 id를 상세 GET의 `before`로 전달한다. `q`, 딜 `pipelineId/archived=true`, 할 일 `status=open/done/cancelled` 필터를 지원한다.

## 데이터와 검증

마이그레이션 `0090_customer_sales.sql`은 파이프라인·딜·딜 이력·할 일 테이블을 추가한다. 기존 운영 DB/레코드/메일은 변경하지 않았다. 이 기능이 운영에 배포됐다고 판단하지 않는다. 개발자 검토용 `dev`와 초안 PR에서 확인한다.

`node --import tsx scripts/check-customer-sales.cjs`는 격리 PGlite에서 기존 플랫폼 API 11개와 영업 API/SQL 13개를 검사한다. 생성 멱등성, 사업/권한 경계, 관계 검증, 단계 감사, 버전 충돌, 사용 단계 삭제 차단, 완료·재개·취소, 보관·복원, SDK, 직원 API 권한, 100건 초과 목록과 동일 시각 이력 커서를 검증한다.

브라우저에서는 디하 단계 변경→연결 업무 생성→완료, 백오피스랩 독립 파이프라인/딜 생성, 고객·회사 관계 저장, 행동 이력 표시, 두 창의 동시 편집 충돌과 최신 내용 복원을 확인했다. 모두 로컬 가상 데이터다.
