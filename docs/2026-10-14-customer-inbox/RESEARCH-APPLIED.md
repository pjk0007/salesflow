# 제공 리서치 반영 · 상담과 CRM의 공통 고객 흐름

2026-10-14 사용자가 제공한 리서치를 기존 요구사항 R01~R16에 대조했다. 문서의 추천을 전부 설치하거나 모든 기능을 완료한 것으로 취급하지 않는다. 우선 제시된 첫 목표인 **고객 문의 → 기존 고객·회사·진행 거래 확인 → 상담 중 딜·후속 업무 생성 → 같은 고객 타임라인 기록**을 구현·검증했다.

## 구현한 흐름

1. 회원 상담의 오른쪽 **고객과 영업** 패널에서 같은 사업의 고객·연결 회사·진행 거래·예정된 업무를 조회한다. 회사의 다른 담당자 거래는 ‘회사 거래’로 구분한다. 종료/보관 거래와 완료/취소 업무를 예정 항목에 섞지 않는다.
2. **딜 만들기 / 후속 업무 만들기**는 기존 편집 폼을 재사용하며 고객·회사를 미리 연결한다. 다른 팀원의 선행 수정은 버전 충돌로 막고 최신 내용 다시 불러오기를 제공한다.
3. `crm_activities`에 상담 공개 메시지·고객 이벤트·딜 변경·업무 생성/완료/재개/취소를 기록한다. 원본 저장과 같은 트랜잭션에서 처리하고 이벤트 키로 중복을 막는다. 고객 연결을 바꾸면 이전 고객에는 연결 해제 기록을 남긴다.
4. 인박스와 고객 관리 화면이 **고객 타임라인**을 함께 읽는다. 내부 상담 메모는 제외한다. 이벤트 상세는 펼쳐 볼 수 있고 기록은 100개씩 이어 조회한다.
5. 이미 저장된 이벤트·딜 감사·공개 상담은 확인 가능한 기록으로 복원한다. 과거 업무 변경 이력은 없으므로 현재 상태를 ‘기존 상태’로만 표시한다. 삭제된 고객의 과거 감사 ID를 유효한 고객으로 임의 연결하지 않는다.

익명 상담의 입력 이메일을 근거로 기존 CRM 고객과 자동 연결하지 않는다. 패널은 서버가 식별한 회원 상담을 대상으로 한다. R03 후속으로 현재 비회원 세션과 서버 확인 회원 JWT를 함께 검증해 이력을 연결하는 API·SDK를 구현했다. 회원 간 CRM 병합과 기존 서비스 데이터 이전은 남아 있다. 메일·사이트 체류 기반 기존 여정과 고객 카드 전송 정책은 수정하지 않았다. [IDENTITY.md](IDENTITY.md)에 계약·검증을 기록했다.

## 검증

`scripts/check-customer-activities.cjs`는 기존 플랫폼 11개·영업 13개에 더해 결합 흐름 7개를 검사한다. 고객/회사/진행 거래 범위, 생성·완료 타임라인, 공개 상담·이벤트 중복과 메모 제외, 원본/활동 롤백, 동일 시각 100건 초과 커서, 기존 기록 복원, 직원 API 인증·조직 경계를 확인했다.

브라우저에서는 상담 안에서 회사/거래 확인 → 후속 업무 생성 → 딜 생성 → 업무 완료 → 같은 고객 타임라인 확인을 직접 수행했다. 로컬 PGlite와 가상 고객만 사용하며 실제 고객 연락·Google Chat 발송·운영 DB 접근은 없다.
