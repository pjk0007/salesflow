# 사업 업무시간에 맞춘 상담팀 자동 배정

2026-10-15 · `dev` / 초안 PR14. 0109 SQL을 추가했다. 운영/개발 고객 DB·서버 설정·키·실제 사이트·main/master 병합·배포는 변경하지 않았다.

## 사용 흐름

1. **고객 상담 → 상담팀 → 사업 업무시간 설정**에서 시간대·요일별 구간·점심 휴게·휴무일을 저장한다. 기존 **운영·성과**와 같은 설정이다. 팀 이름·업무·팀원 초안을 유지한 채 달력을 수정할 수 있다.
2. 팀의 자동 배정을 켜고 **사업 업무시간에만 자동 배정**을 선택해 팀을 저장한다. 새 옵션은 기본 꺼짐이다. 달력을 명시적으로 저장하지 않았으면 먼저 저장하도록 안내하며 팀 변경은 저장하지 않는다. 응대 목표와 사이트 시간 안내를 끄더라도 저장한 달력을 배정에 사용할 수 있다.
3. 업무시간 밖·점심 휴게·휴무일에는 자동 담당자를 고르지 않고 팀 대기열에 둔다. 팀 목록과 담당 정보에 시간대·현재 상태·다음 업무 시작을 표시한다. 다른 사업의 달력을 섞지 않는다.
4. 업무 시작 후 **배정 수용량 → 대기 상담 배정**으로 대기 상담을 확인한다. 별도로 켠 기존 큐 워커도 같은 검사를15초마다 수행한다. 워커는 기본 꺼짐이며 이번 검토에서 활성화하지 않았다. 업무시간이 열려 있어도 접속/응대 가능·현재 권한·수용량 조건을 모두 만족해야 배정한다.
5. 달력 변경은 다음 배정 판단부터 최신 값으로 반영한다. 이미 맡은 상담을 해제/재배정하지 않는다. 사람이 명시적으로 지정하는 담당자는 시간 제한을 넘겨 선택할 수 있으며 수동 팀을 자동 팀으로 바꾸지 않는다.

사업별 달력을 재사용하며 직원별 교대표나 서로 다른 팀 전용 시간표를 만드는 기능은 아니다. 팀마다 이 사업의 달력을 적용할지 선택한다. 현재 상태는 기존 목록/상담 갱신 주기를 따르므로 화면은 잠시 이전 상태를 보일 수 있지만 서버는 배정 시점에 다시 확인한다.

## 적용 시점과 자동화

SLA의 진행 중·과거 응대는 원래 저장한 목표/달력으로 계속 계산한다. 새 응대는 새 설정을 쓴다. 팀 배정은 다음 판단부터 최신 달력을 쓰므로 기존 대기 상담에도 적용한다. 두 계약을 구분하도록 공통 편집기의 버튼을 **운영 설정 저장**으로 바꾸고 설명과 저장 안내를 보완했다.

조건별 자동화는 모의 실행에서도 시간 조건과 대기 사유/다음 업무 시작을 보여주되 배정하지 않는다. 사람이 게시한 이후 실제 실행에서는 그때의 달력·팀·권한·상담 수를 다시 확인한다. 모의 실행 이후 업무시간이 열리거나 닫히는 두 방향을 검수했다. AI가 지정한 사람에게 새로 이관하는 경우도 현재 팀의 시간 제한을 따른다. 기존 개인 담당은 유지한다. 팀 없이 지정한 AI 이관은 특정 팀의 달력을 임의로 적용하지 않는다.

달력이 사라진 가상 오류 사례에서도 기본24시간 달력으로 자동 대체하지 않고 미배정으로 남긴다. 이 경우 목록에 미설정 상태를 표시한다. 실제 앱에는 달력 삭제 API를 추가하지 않았다.

## API/SDK와 설치

| 계약 | 추가 내용 |
|---|---|
| 기존 native/서비스 팀 POST | 선택 `requireBusinessHours:boolean`, 기본false. 사용 시 이 사업에 저장한 달력 필요 |
| 기존 팀 PATCH | 선택 `requireBusinessHours`, 생략 시 보존. 기존 version/CAS·멱등·감사·사업 manage 권한 유지 |
| 기존 팀 GET·상담 bootstrap | `requireBusinessHours`와 `businessHours:{configured,open,timezone,nextOpenAt}\|null`. 제한을 끄면null |
| 기존 대기열 재처리·팀 이관·자동화·AI 이관 | 같은 서버 시간 조건을 확인. 새 권한이나 외부 발송 API 없음 |

`SendbClient.createInboxTeam`, `updateInboxTeam`, `inboxTeams`와 `sdk/routing-types.ts`에 계약을 반영했다. 키 범위와 발급자의 현재 사업 역할을 함께 확인한다. 기존 클라이언트의 생략값과 기존 팀은 제한을 끈 상태로 유지한다.

`0109_inbox_team_business_hours.sql`은 팀의 `require_business_hours boolean NOT NULL DEFAULT false`만 추가한다. 검토/설치 시 앱보다 먼저0088~0109 마이그레이션이 필요하다. 이번에는 가상 시험 DB에만 실행했다. 시간대·DST·구간·휴무일 계산은 기존 `inbox-operations/calendar.ts`를 재사용했다.
