# 개발 샌드비 체험 준비

2026-10-15 사용자가 `dev` 반영과 직접 체험·가이드를 요청했다. 이전의 로컬 전용 범위에서 **샌드비 dev와 sendb-dev 개발 서비스**만 확대한다. 운영 main/sendb/sendb-db, 실제 사이트 공급자 전환은 이번 범위가 아니다.

개발 주소: https://port-next-sendb-dev-1ru12mlw8nvyar.sel5.cloudtype.app

- 체험 시작: `/dev-start/index.html`
- 단계별 가이드: `/dev-start/guide/index.html`
- 가상 채널톡 JSON: `/dev-start/sample-channel-history.json`
- 실제 기능: `/inbox`, `/customer-crm`, `/customer-ai`, `/customer-workflows`, `/customer-imports`

사용자는 기존 샌드비 계정으로 개발 서버에 로그인한다. 실제 자료와 구분되는 체험용 사업에서 가상 JSON을 채널톡·JSON·원본 계정 `sendb-demo-20261015`로 미리보기한 뒤 실행한다. 가상 고객1·상담1·공개 대화2·직원 메모1이며 파일/원본 계정 호출·발송 동작은 없다. 고객 공개 확인은 기본 꺼짐으로 유지한다. 실제 회원 ID 매핑이 없는 샘플을 고객 본인 공개 승인에 사용하지 않는다.

기존 브랜치의 가상 API/SDK/빌드 검증을 재사용하고 공개 시작 안내·가이드 자산·예시 JSON의 변경만 추가 검사한다. 공개 가이드는 기존 오프라인 자료를 복사하되 개발 기능 진입 링크와 현재 설명을 구분했다. 가상 캡처를 최신 배포 화면으로 설명하지 않는다.

## DB와 발송 범위

이전 로컬 구현·검수에서는 실제 개발/운영 DB를 변경하지 않았다. 현재 개발 서비스의 마지막 배포는 `2e18c6b`이며, 최신 플랫폼을 구동하려면 0088~0112의 미적용 마이그레이션이 있을 수 있다. 기존 서버의 시작 시 마이그레이션 절차를 따른다. 새로 추가한 과거 상담 본인 공개 기능 자체에는 추가 SQL/스키마가 없다.

CloudType의 `sendb-dev`·`dev`와 개발 DB 연결을 먼저 확인한다. 개발 DB는 기존 운영 복사본을 포함하므로 실제 고객 발송, 고객 원본 삭제·재복사, 공유 R2 파일 삭제는 하지 않는다. 개발 서비스의 확인된 `NEXT_PUBLIC_APP_URL`과 정확히 일치하는 런타임에서는 시작 시 모든 자동 워커를 건너뛴다. 기존 운영 주소에서는 워커의 기존 설정을 유지한다. 관리 화면에서 자동 워커 off 값도 명시한다. 이 제한은 수동 API 자체를 모두 모의 실행으로 바꾸는 계약이 아니므로 체험은 가상 고객으로 한다.

코드 푸시·빌드 완료·서비스 적용·DB 마이그레이션 성공·사용자 화면 확인은 각각 구분해 기록한다. 이 문서는 준비 절차이며 배포 완료 판정은 실제 배포 후 인수 기록에 남긴다. 전체 채널톡 대체 완료나 운영 승인을 뜻하지 않는다.

## 개발 배포 결과물

CloudType의 Standalone 결과물에 `drizzle/meta/_journal.json`이 없어 최초 `b128f2e` 실행은 마이그레이션 전에 중단됐다. 실패를 무시하는 설정은 사용하지 않는다. `output: standalone`과 `pnpm run build:cloudtype`로 빌드하고, 복사 스크립트가 standalone 서버에 전체 drizzle 파일을 포함한 뒤 journal의 SQL별 해시를 검증한다. 이 빌드 스크립트는 DB에 접속하거나 마이그레이션을 실행하지 않는다. DB 적용은 개발 서버의 기존 시작 절차에서만 이뤄진다.
