# 기존 리드 → 방문 → 상담 연결

2026-10-15 사용자 요청: 샌드비가 메일·알림톡을 보낸 기존 리드가 사이트 하단 상담을 시작하면 직원이 이전 경로를 한 화면에서 확인한다. dev 기능이며 실제 디하/백오랩 사이트의 기존 채널톡 설치는 전환하지 않는다.

## 직원 화면

상담 오른쪽 **발송·방문·상담 경로**에 발송, 메일 클릭, 방문 페이지·행동, 상담 공개 메시지를 시각순으로 표시한다. 내부 메모는 여정에서 제외한다. 20건씩 이전 경로를 더 볼 수 있다.

dev 브라우저에서 가상 발송→세 페이지 방문→문의→직원 답변→같은 리드 회원 연결을 확인했다. 첫 검수의 방문 요약이 ‘직접 유입’으로 보이는 혼동을 제거하고, 회원/직원 연결로 상담 버전이 바뀌면 경로 패널을 즉시 새로 읽도록 보완한다.

- **메일 링크 유입 · 본인 미확인**: 현재 방문 세션의 메일 클릭을 같은 사업의 수신 리드에 대조한다. 수신 리드의 기록이라는 근거이며 상담 고객을 자동 병합하지 않는다.
- **방문 경로 유입 · 본인 미확인**: 현재 브라우저에 기존 리드 연결이 한 개만 있을 때의 관측 관계다. 여러 리드가 있으면 첫 고객을 고르지 않는다.
- **확인된 고객 연결**: 기존 직원 확인 연결 또는 사이트 서버가 확인한 회원의 CRM 연결이다. 링크 수신 리드와 다르면 확인된 고객의 기록을 우선하며 서로 다른 고객의 발송 이력을 섞지 않는다.
- **기존 리드 연결 전**: 근거가 없는 문의도 접수한다. 고객을 확인해 기존 레코드에 연결할 수 있다.

입력 이메일/전화/이름을 같은 고객의 증명으로 사용하지 않는다. 메일 링크는 공유될 수 있고 브라우저는 공동 사용할 수 있다. 유입 후보로는 회원 인증이나 과거 고객 공개 열람 권한을 발급하지 않는다.

## 자동 연결

같은 사이트에 현재 tracker.js와 sendb-sdk.js 1.5 이상을 설치한다. 트래커의 첫 수집·후속 수집에서 30분 경로 증명을 메모리로 전달하고 SDK가 상담 iframe에 넘긴다. 고객이 직접 보낸 문의에만 현재 상담/세션 관계를 저장한다. 트래커와 상담 SDK의 설치 순서가 달라도 최초/늦은 수신을 처리한다. 만료나 연결 실패가 이미 전송한 문의를 취소하지 않는다.

회원 로그인은 기존 서버 확인 JWT 계약을 유지한다. `/api/v1/inbox/sessions`에서 서비스 키에 수정 권한이 있을 때만 같은 사업의 활성 트래커 `matchField`를 회원 `externalId`와 대조한다. 유일한 기존 레코드일 때 자동 연결하고, 필드 미설정/중복은 그대로 둔다. 수정 권한이 없는 기존 세션 발급도 계속 가능하다. 실제 사이트 서버가 Firebase 등으로 확인한 ID를 보내야 하며 브라우저 본문의 ID를 믿지 않는다.

상담 경로 조회는 사업별 직원 권한을 재확인한다. 기존 리드 한 개의 기록만 읽으며 방문 브라우저를 거쳐 다른 리드까지 자동 병합하지 않는다. 과거 채널톡 상담은 이미 같은 CRM 고객으로 매핑된 공개 메시지만 직원 여정에 포함한다. 과거 상담 원문을 수정하거나 고객 공개 승인을 바꾸지 않는다. 소스 회원 ID가 확인되지 않은 과거 자료는 자동 연결 대상이 아니다.

## API·DB

- `POST /api/messenger/{key}`의 `action:"journey"`: 현재 상담 토큰 + `journeyToken`과 선택 `conversationId`. 경로의 사업/사이트/출처/방문 세션을 검증하며 직원용 관계만 저장한다.
- `GET /api/inbox/conversations/{id}/journey`: 직원 전용 경로 패널 자료.
- Headless `SendbMessengerClient.attachJourneyContext(token, conversationId?)`.
- `0113_inbox_lead_journey.sql`: `inbox_conversations.journey_context` nullable JSON 컬럼 하나. 고객/발송/방문 자료 삭제·일괄 재매칭 없음.

알림톡 발송 이력은 연결된 리드 기준으로 함께 표시한다. 알림톡 링크 자체의 신규 추적 리디렉터나 실제 카카오 상담 수신 연동을 새로 구현한 것은 아니다. 실제 사이트에 기존 SDK가 남아 있으면 이번 연결은 시작되지 않으므로 사이트 어댑터/SDK 업데이트와 실제 회원 ID 매핑을 별도로 확인해야 한다.

## dev 체험

`/dev-start/journey-demo.html`에서 가상 리드·발송 기록 준비 → 서비스/가격 페이지 이동 → 하단 상담 전송 → 직원 상담함 경로 확인 → 가상 회원 확인·현재 문의 연결 순서다. 실제 메일/알림톡을 보내지 않으며 기록의 상태는 `demo`다. 회원 확인 버튼은 실제 로그인 대신 고정된 가상 회원을 사용한다.

가상 자료 준비 API는 정확한 dev 런타임·관리자·이름이 고정된 체험 사업에서만 작동한다. 일반 사업과 운영에서는 자료를 만들지 않는다. 회원 JWT는 사이트 저장소에 보관하지 않는다. dev 자동 워커 중지 정책을 유지한다.
