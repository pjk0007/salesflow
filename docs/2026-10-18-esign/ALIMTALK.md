# 전자서명 이메일·알림톡 연결

2026-10-18 사용자 요청에 따라 기존 조직 계정을 재사용한다. 새 SMS 계정·발신번호 등록은 이메일과 알림톡 이용의 필수 조건이 아니다. 현재 개발 환경만 연결하며 운영 `main`과 운영 DB는 변경하지 않는다.

## 신청 결과

발신 채널은 **@디자이너하이어**다. NHN KakaoTalk Bizmessage의 기존 프로젝트에서 아래 3종을 새로 등록했다. 등록 요청이 심사 신청을 시작하며, 실제 API 조회와 콘솔에서 세 건 모두 **TSC02 / 검수 중**임을 확인했다. 심사 담당자에게 정보성 계약 안내·직접 요청한 인증·완료 파일 안내라는 용도와 실제/개발 링크 차이를 보충 설명했고 각 댓글의 저장을 확인했다. 기존 승인 템플릿은 수정하지 않았다.

| 용도 | 코드 | 분류 | 현재 상태 |
| --- | --- | --- | --- |
| 서명 요청 | `SB_ESIGN_REQ_V1` | 계약/견적 | 검수 중 |
| 인증 코드 | `SB_ESIGN_OTP_V1` | 인증/비밀번호/로그인 | 검수 중 |
| 완료 알림 | `SB_ESIGN_DONE_V1` | 계약/견적 | 검수 중 |

실제 신청 본문·버튼·변수는 [alimtalk-templates.json](../../src/lib/esign/alimtalk-templates.json)을 단일 기준으로 사용한다. 기본 정보성·보안 템플릿이며 광고·채널 추가·판촉 문구가 없다. 이름/문서명과 HTTPS 서명 링크를 치환한다. 인증 코드 템플릿은 6자리 코드와 서버와 같은 5분 유효시간을 안내한다. 완료 알림은 모든 서명이 모이고 완료 PDF 저장·검증이 끝난 뒤 보낸다.

## 사용자 동작

1. 전자서명 화면에서 이메일 준비 상태, 알림톡 발신 채널과 템플릿별 심사 상태를 확인한다.
2. PDF 또는 템플릿을 준비하고 받는 사람의 이름·이메일·국내 휴대폰 번호를 입력한다.
3. 이메일/알림톡을 선택한다. 알림톡은 세 템플릿 모두 승인돼야 선택할 수 있다. 심사 중에는 이메일만 선택한다.
4. 요청 후 상세에서 채널별 접수 결과를 확인한다. 같은 수신자의 두 채널은 같은 서명 링크를 사용한다.
5. 고객은 등록된 채널 중 하나로 인증 코드를 받고 서명한다. 완료 알림도 처음 선택한 채널로 전달된다.

`승인 상태 새로고침`으로 NHN 상태를 다시 읽는다. 세 템플릿이 승인되고 발신 채널도 정상이면 추가 코드 배포 없이 알림톡 사용 가능으로 바뀐다. 반려·차단·휴면 또는 신청 본문/버튼 변경 시에는 계속 차단한다. 심사자가 보안 설정이나 문구를 변경했다면 실제 승인 결과를 검토하고 버전을 맞춘다. 승인 여부를 환경 변수로 강제하지 않는다.

현재 채널은 조직 단위로 고정하며 사업별 자동 선택은 없다. 다른 사업에서 요청할 때 화면의 **알림톡 발신 채널**을 확인해야 한다. 백오피스랩 등 다른 채널을 사용하려면 해당 채널에도 3종을 신청하고 별도로 연결한다.

## 서버 설정과 영향

- `ESIGN_ALIMTALK=on`: 전자서명 알림톡 전용 opt-in. 미지정 시 off다.
- `ESIGN_ALIMTALK_SENDER_KEY`: 선택한 기존 발신 채널 고정. 미지정 시 해당 조직의 기본 채널을 사용한다. 값은 서버 비밀 설정에만 둔다.
- 기존 `alimtalk_configs`에서 인증된 조직의 계정만 읽는다. 기존 조직 활성화 상태도 존중한다. 기존 설정·영업 자동화·발송 큐는 변경하지 않는다.
- `ESIGN_EMAIL_SENDER=ceo@matchesplan.com`은 유지한다. 기존 영업 이메일 기본 발신자는 바꾸지 않는다.
- 기존 `esign` 작업 대기열과 15초 worker를 재사용한다. 새 스키마·외부 서비스·파일 저장 방식 변경은 없다.
- 알림톡은 종류별 승인 상태를 송신 직전에 확인한다. 일반 요청·완료는 `/messages`, 코드는 `/auth/messages`를 사용한다. 인증 코드·서명 링크·공급자 키를 로그에 쓰지 않는다.
- `resendParameter.isResend=false`를 명시하므로 SMS로 자동 전환하지 않는다. 공급자 idempotency key는 작업 ID다. 접수 불명/타임아웃을 성공으로 표시하거나 자동 재발송하지 않는다.

공급자 접수와 고객 실제 수신은 다르다. 승인 후 사용자가 지정한 내부 휴대폰으로 요청·코드·완료 수신을 확인해야 한다. 이번 작업에서는 실제 카카오/SMS 메시지를 보내지 않았다. 계약 전체 실제 이메일 수신 검수도 아직 완료로 기록하지 않는다.
