# 디하 고객 상담 원문 → Google Chat

사용자는 브라우저 사운드/알림 구현을 취소하고 `1-디자이너하이어-고객상담알림` 스페이스에 고객 메시지 원문과 상담 바로 열기를 요청했다. 해당 비공개 스페이스를 만들었으며 웹훅 생성·운영 연결은 사용자가 별도로 승인했다.

## 동작

- 연결 이후 발생하는 디하의 **새 고객 메시지**만 보낸다. 웹·이메일 고객 원문과 줄바꿈을 보존한다. 직원 답장·내부 메모·과거 수입 이력·내부자·병합된 이력은 제외한다. 과거 문의를 일괄 재발송하지 않는다.
- 구글챗 카드에 고객 이름, 상담 채널, 원문, 시각, 첨부 파일명, **샌드비에서 상담 열기** 버튼을 표시한다. 파일은 샌드비의 기존 인증을 거쳐 확인한다. 첨부를 공개하거나 구글챗으로 재업로드하지 않는다.
- HTML/멘션처럼 보이는 원문도 카드 안에서 문자로 표시한다. 긴 본문은 Unicode 글자 단위로 나눠 전체를 보내고, 같은 상담은 같은 구글챗 대화목록으로 묶는다.
- 구글챗에서 답장을 써도 고객에게 전달되지 않는다. 버튼으로 샌드비를 연 뒤 답변한다. 닫힘/보류 상담 링크도 해당 상담과 상태를 넘긴다. `message` 쿼리는 기존 내부 메모 전용이므로 고객 카드에는 넣지 않는다. 실제 버튼 검수에서 발견한 메모 팝업 오류를 회귀 검사에 추가했다.

## 설정과 구조

새 패키지나 외부 자동화 서버는 없다. 고객 메시지 저장 트랜잭션에서 작은 `inbox_chat_alert_deliveries` 대기열만 만들고, 기존 Next Node 프로세스의 5초 주기 워커가 커밋 후 전송한다. 화면을 닫아도 서버가 처리한다. 기존 Google Chat 전송 간격·오류 정리 함수를 재사용한다.

- `INBOX_CHAT_ALERTS=on`
- `INBOX_CHAT_ALERT_ROUTES`: 조직 UUID·사업 ID·상담 채널 ID·웹훅의 JSON 배열. 모두 일치해야 한다. 운영에서 확인한 디하는 사업 **8**, 채널 **1**이다. 비밀 주소는 저장소·로그·이 문서에 넣지 않는다.
- 형식 예시: `[{"orgId":"조직 UUID","workspaceId":8,"channelId":1,"webhook":"Google Chat 비밀 웹훅"}]`
- 수신 스페이스: https://chat.google.com/app/chat/AAQAUofV52w
- 개발 체험 서버는 이 설정을 복사해도 대기열/워커가 작동하지 않는다. 로컬 격리 자료와 가상 전송기로 검수한다.
- 마이그레이션 `0117_inbox_chat_alerts.sql`은 전송 대기/결과 테이블과 대기 색인만 추가한다. 고객 원문을 복사하거나 수정하지 않는다.

동일 메시지의 대기는 PK로 한 번만 생긴다. 짧은 DB 잠금으로 작업을 선점하고 외부 요청 중에는 트랜잭션을 잡지 않는다. 부분 성공을 기록하며 재시도 시 성공한 부분은 건너뛴다. 각 부분은 고정 `messageId=client-inbox-…`를 사용한다. 실제 웹훅은 `requestId`를 400으로 거절하므로 이 기능은 해당 옵션을 사용하지 않는다. 고정 messageId의 재요청은 409(이미 있음)를 성공으로 처리한다. 진단 가상 카드로 최초 성공과 동일 ID의 409를 확인했다. 실패는 최대 8회 재시도 후 보존한다. 400/401/403/404 등 확정 거절은 중지한다. 주소가 바뀌면 기존 설정으로 생긴 대기를 취소한다. `INBOX_CHAT_ALERTS=off`로 새 대기/자동 발송을 중지한다.

- 격리 PostgreSQL(PGlite) 검사 13개: 원본 트랜잭션과 롤백, 실제 저장 경로, 중복 제출, 두 워커 동시 처리, 내부 메모/사업/이력 분리, 원문 카드, 부분 실패 복구, 설정 변경 취소, 확정 오류 중지. 외부 메시지 0건. SQL 재실행도 통과했다.
- 배포 webpack 빌드·타입·페이지 생성·standalone 마이그레이션 복사 통과. 실제 운영 비밀 설정은 로컬에 로드하지 않았다.
- 기존 운영 검사에는 10월 16~20일의 고정 가상 시각을 쓰는 항목이 있어 10월 19일 실시간 실행에서는 정책 적용 시각 비교가 실패한다. 해당 자료보다 앞선 **2026-10-15T00:00:00Z로 Date만 고정**하여 회귀 검사를 수행한다. 제품 시계/운영 설정은 바꾸지 않는다.
- 근거 폴더: `F:/Dev/.work/inbox-chat-alerts-20261019/`. 운영 적용·실제 구글챗 수신 결과는 확인 후 추가한다.

## 후속 요청: 직원 프로필과 고객 타임라인

사용자가 각 1건 테스트 발송을 승인한 이효정(senior_hj@matchesplan.com), 임지연(lim@matchesplan.com), 양윤지(yj@matchesplan.com), 안다솜(dsa@matchesplan.com)의 운영 발신자 프로필을 UI에서 발송 확인 후 저장했다. 프로필 ID는 165~168이며 기존 기본 발신자는 유지했다. 테스트 결과는 발송 서비스 접수 성공이며 수신함 열람을 대신하는 결과는 아니다.

고객 정보에는 메일·알림톡·사이트 방문 페이지/행동·CRM 고객 정보/딜/업무/이벤트·상담 시작과 최근 진행을 시간순으로 즉시 표시한다. 기존 접기 및 20건 제한을 제거한다. 채팅 원문은 중앙 상담 창에 두고 타임라인에서는 상담별 문의/답변 수로 요약한다. CRM 활동은 같은 조직·사업·명시된 고객 연결만 조회하며, 리드 번호가 없는 확인된 CRM 고객도 포함한다. 이메일만 같은 다른 고객을 합치지 않는다. 공유 링크의 유입 추정 표시는 유지한다. 기존 데이터 조회만 확장하므로 추가 DB 변경은 없다.
