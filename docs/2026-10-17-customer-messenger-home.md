# 디하 고객용 상담 첫 화면

고객이 디자이너하이어 사이트에서 상담 버튼을 처음 열면 최근 대화나 이름 입력 화면 대신 브랜드 안내 홈을 보여준다. 채널톡 고객 홈에서 확인한 브랜드 헤더·안내 카드·문의하기·대화 목록의 순서를 따른다.

## 고객 동선

1. 안내 홈의 ‘문의하기’를 눌러 질문을 작성한다. 이름과 이메일은 선택 입력이다. 입력하지 않은 방문자는 ‘방문 고객’이라는 표시명으로 기존 익명 세션을 만든다.
2. 확인된 회원은 새 문의를 시작하거나 ‘이전 대화 이어보기’에서 자신의 문의를 선택한다. 비회원은 현재 브라우저에 연결된 기존 대화를 이어본다.
3. 하단 홈·대화 메뉴로 이동한다. 홈을 다녀와도 작성 중인 문의와 첨부 상태를 유지한다. 같은 페이지에서 상담창을 닫았다 다시 열면 사용 중인 화면을 유지한다.
4. 홈이나 대화 목록을 보는 동안에는 답변 알림을 읽음 처리하지 않는다. 실제 대화를 연 뒤에만 읽음 처리한다.

운영시간은 기존 공개 설정이 있을 때만 안내한다. 확인되지 않은 응답 시간이나 상담원 사진을 만들지 않는다. API·고객 식별·과거 기록 공개 범위·내부 메모 제외 규칙은 유지한다. 방문자 이름·이메일만으로 회원이나 기존 CRM 고객으로 승격하지 않는다.

사이트에서 전달하는 신청 내용 초안과 SDK의 특정 대화 열기는 기존 계약을 유지한다. 자동으로 새 고객 문의를 보내지 않는다. 기존 상담·첨부파일·운영 데이터는 삭제하거나 이동하지 않는다.

## 배포와 검수

고객 UI는 사이트 내부 정적 파일로 배포되므로 디하의 HTML·JS·CSS와 SDK 파일을 새 해시로 교체한다. 백오피스랩의 기존 UI 파일은 이번 디하 배포에서 변경하지 않는다. 이미 두 사업에서 검수한 AI 자동 응대는 유지한다.

격리 DB와 가상 고객을 사용해 비회원 이름 미입력 전송, 회원 문의, 초안 유지, 홈의 미확인 답변 유지, 대화 목록 및 실제 대화 읽음을 검수한다. SDK 30개·실제 디하 어댑터 7개·고객 대화/오리진 단위 24개 검사와 타입·lint·빌드를 확인한다. 디하 배포 후 첫 화면과 새 QA 문의의 자동 응대도 확인한다.
