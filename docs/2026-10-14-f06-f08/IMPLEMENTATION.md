## 보존할 동작

고객별 LLM 문구 변주와 동일 작업 재시도의 본문 재사용을 유지한다. 7초 이상 유효 방문의 후속 중단과 30~60분 뒤 업무시간 감사 메일, 60초 이상 고객여정 Chat 기준을 바꾸지 않는다. 실험 A와 B는 작성 정책을 비교하며 고객에게 두 메일을 보내지 않는다. 실험의 모델, 지식, 제목, 발송 조건은 시작 시 고정한다.

## 평소 발송의 자동 관찰 (2026-10-14 추가)

별도 실험을 만들지 않은 평소 AI 첫 메일과 방문 감사 메일을 F08·F06 기본 탭인 `자동 관찰`에서 확인한다. 기존 생성 작업과 전송 장부를 읽어 집계하며 발송 경로·본문·모델·예약 시간은 변경하지 않는다. 새 DB 마이그레이션이나 추가 LLM 호출은 없다.

- F08: 첫 생성 성공률, 대기·재시도를 포함한 준비 p95/p99, 30분 내 준비율, 본문·질문 반복 비율, 실패·재작성 시도를 포함한 비용을 표시한다. 단가나 사용량이 빠진 비용은 확인 필요로 남긴다. 실제 모델 승인 및 통제 부하 시험과 구분한다.
- F06: 일반 첫 메일을 사업·규칙·지침별로 모아 발송 고객과 14일 관찰 완료 고객, 사람 회신 고객을 표시한다. 내부 계정·자동 응답·반송·dry run 회신과 기존 A/B 배정은 일반 발송 성과에서 제외한다. 동일 규칙·지침으로 재발송한 고객은 첫 발송 한 번만 분모에 넣고 해당 전송의 14일 창을 사용한다. 긍정 회신이나 A/B 인과 효과로 해석하지 않는다.
- 회신 연결과 최근 수집 상태가 확인되지 않으면 회신율 대신 `회신 수집 확인 필요`를 표시한다. 일반 발송을 자동으로 새 실험에 편입하거나 후보를 승인·시작·채택하는 변경은 포함하지 않는다.
- 조회 범위는 최근 30일, 최대 최신 5,000 작업이다. 제한을 넘으면 최신 작업 범위의 부분 요약임을 화면과 API에 표시한다. 준비 전 내부 고객은 이메일이 발송 장부에 연결된 뒤 제외할 수 있다.

검증: 전체 단위 테스트 1,024개, TypeScript 및 변경 코드 ESLint 통과. 격리 PGlite 검사 37개 통과(일반 발송 회신·연결 미확인 표시·사업 범위 검사 추가). 실제 제품 컴포넌트와 API를 격리 로컬 DB에 연결해 Chrome에서 기본 탭과 사업 필터를 확인했다. 실제 고객 발송과 운영 DB 접근은 없다. 아직 운영에 적용하지 않았다.

## 통계 구현 근거

차이의 95% 구간은 독립 Wilson 구간을 결합하는 Newcombe 방법을 사용한다. 사건이 0건이어도 구간 폭을 0으로 단정하지 않는다. [원 논문](https://doi.org/10.1002/(SICI)1097-0258(19980430)17:8%3C873::AID-SIM779%3E3.0.CO;2-I)

SRM은 배정 200명 이후 1:1 비율의 카이제곱 검사로 확인하며 p<0.0005이면 판단을 보류한다. 이 기준은 Microsoft의 보수적인 검토 기준을 참고했다. [Microsoft Research](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/)
