## 보존할 동작

고객별 LLM 문구 변주와 동일 작업 재시도의 본문 재사용을 유지한다. 7초 이상 유효 방문의 후속 중단과 30~60분 뒤 업무시간 감사 메일, 60초 이상 고객여정 Chat 기준을 바꾸지 않는다. 실험 A와 B는 작성 정책을 비교하며 고객에게 두 메일을 보내지 않는다. 실험의 모델, 지식, 제목, 발송 조건은 시작 시 고정한다.

## 검증 해석

성능 수치는 기획서의 초기 목표이며 실측으로 확인한다. 실제 사람 두 명의 독립 평가는 자동 테스트나 LLM 평가로 대체하지 않는다. 기능 배포와 문구 버전의 승인 및 고객 대상 실험 시작은 별도 상태로 기록한다. 승인되지 않은 버전을 자동으로 발송에 연결하지 않는다.

- `node --import tsx scripts/check-email-experiments.cjs`: 1,201개 가상 배정과 실험·재작성·취소·API·독립 검수 관문을 검사한다. SQL 마이그레이션과 Drizzle의 컬럼·참조 일치도 확인한다. 이 스크립트의 승인과 생성 결과는 기능 경계 검사용 fixture이며 사람 평가나 모델 성능 실측이 아니다.
- 기존 감사 메일 19개 SQL 시나리오, 가상 명단 1,010건의 무작위 예약·준비·전송 경계 검사 통과. 외부 요청과 실제 고객 시험 발송은 0건이다.
- 실제 컴포넌트를 사용하는 별도 localhost 화면에 가상 응답만 공급해 Chrome QA를 수행했다. 지침·성능 입력, 변경 근거 누락 차단·복구, 평가 보류·비용 미확인, 생성 시간 초과·부분 사용량, 결과·성과 입력·실험 초안, 390px 모바일 모달과 가로 넘침을 확인했다. QA 하네스와 가상 데이터는 Git에 포함하지 않는다.
- 실제 LLM 400건 품질 평가, 담당자 두 명의 80건 독립 평가, 630건 통제 부하 실측은 **미수행**이다. 지연·다양성·자연스러움·비용 목표를 충족했다고 주장하지 않는다. 해당 근거 없이 새 정책을 승인·발송 연결할 수 없다. 이 배포는 이를 수행·검토하는 관리 기능과 계측 경로를 제공한다.
- 첫 소개 메일의 자유형 ‘필수 의미’는 작성 지침과 사람의 목적 적합성 검수에서 확인한다. 자동 검증은 형식·길이·미치환·금지 표현·허용 링크, 감사 메일의 감사·문의·연락 의미를 확인한다. 자유형 의미와 사실성 전반에 대한 자동 보증으로 해석하지 않는다.
- dev와 운영 배포 상태·커밋은 실행 후 이 문서에 기록한다.

## 통계 구현 근거

차이의 95% 구간은 독립 Wilson 구간을 결합하는 Newcombe 방법을 사용한다. 사건이 0건이어도 구간 폭을 0으로 단정하지 않는다. [원 논문](https://doi.org/10.1002/(SICI)1097-0258(19980430)17:8%3C873::AID-SIM779%3E3.0.CO;2-I)

SRM은 배정 200명 이후 1:1 비율의 카이제곱 검사로 확인하며 p<0.0005이면 판단을 보류한다. 이 기준은 Microsoft의 보수적인 검토 기준을 참고했다. [Microsoft Research](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/)
