## 자동 후보 준비·선택형 실험·사람의 최종 적용 (2026-10-14)

사용자가 자동 후보 생성·평가·실험을 요청한 뒤, 최종 적용은 사람이 하고 실험도 수동으로 진행할 수 있게 수정했다. 이후 운영 배포를 명시적으로 요청했다. 최종 적용을 자동화하는 설정이나 스케줄러 호출은 없다.

- F08·F06의 `자동 관찰` 상단에서 사업별 자동 준비를 켠다. 첫 메일 실험 방식은 `자동으로 개설·시작` 또는 `사람이 직접 개설·시작`으로 선택한다. 기존 `새 실험`, 수동 품질 평가·검수·부하 시험은 유지된다.
- 기존 승인 연결을 A로 사용한다. 연결이 없으면 현재 운영 규칙과 등록된 제품 자료를 스냅샷으로 보존하고 `기존 설정 등록`으로 표시한다. 외부 사실 검증·사람 검수를 했다고 기록하지 않는다. 후보는 질문 방식 한 항목만 바꾸고 모델·지식·기타 조건은 유지한다.
- 자동 경로는 가상 문구 A 40건/B 40건, 좌우 순서를 번갈아 배치한 AI 비교 검토 40회를 실제 설정 모델로 수행한다. 사람 검수 테이블을 채우지 않는다. 오류·근거 없는 주장·다양성·속도·입출력 토큰 증가 기준 미달은 보류한다. 40건 지연 표본의 p99는 참고값이며 통제 부하 시험과 구분한다.
- 조직별 자동 준비 호출은 일 180회·30만 토큰을 기준으로 제한하고 기존 조직 쿼터도 확인한다. 모든 시도는 기존 사용량 장부에 기록한다. 여러 사업·규칙이 한도를 공유하며 한도 도달 시 다음 회차에 이어서 진행한다. 성공 결과는 재사용하고 결과가 불명확한 호출은 자동 재호출하지 않는다.
- 첫 메일 자동 실험은 회신 수집 연결과 준비 전 대기 고객을 확인한다. CRM에 명시된 회사 필드만 회사 확인 자료로 사용하고 개인 메일 도메인으로 회사를 추정하지 않는다. 내부 이메일·도메인·사업명은 제외한다. 이미 등록된 회사 확인 정보를 덮어쓰지 않는다.
- 모집 전에 명단과 42일 발신 용량에 맞는 탐지 가능 차이·표본을 동결한다. 초기 회신율 5%, 탐지 차이 2~20%p, 실무 개선폭 1%p, 거절 20%·수신거부 5%·생성 실패 5% 기준의 자동 초기 계획임을 기록한다. 표본 부족·회신 연결 미확인·같은 규칙의 다른 실험 진행 중이면 기다린다. 수동 모드에서는 초안만 준비하고 사람이 시작한다.
- 실제 발송된 실험 고객의 연결된 사람 회신 발췌만 자동 분류한다. 신뢰도 0.9 이상이며 인용이 원문에 실제로 존재할 때만 관심·중립·거절을 인정하고 나머지는 미분류로 남긴다. 사람의 분류·정정은 자동 처리보다 우선하며 수정 이력에 출처·신뢰도를 기록한다.
- 기존 F06의 14일 성숙·표본·SRM·부정 지표·미분류 민감도 검사를 통과하면 `사람의 적용 대기`로 남는다. 방문 감사 메일은 AI 품질 검토 뒤 바로 적용 대기로 남으며 첫 메일 A/B 실험에 편입하지 않는다.
- `결과 검토 후 적용`에서 지침·평가 점수·가상 문구 예시를 읽고 `검토했고 새 작업부터 적용`을 눌러야 연결이 바뀐다. 최신 기준을 재확인하고 연결 변경·적용 기록을 같은 트랜잭션에 저장한다. 기존 준비 본문과 다른 실험은 보존한다. 자동 준비를 꺼도 사람이 시작한 실험을 종료하지 않는다.
- DB 마이그레이션 0087은 앱 시작 시 기존 마이그레이션 경로로 실행한다. 운영 DB에 직접 접속하지 않는다. 완료·보류한 준비 회차의 재생성은 7일 간격이며 최종 적용 대기 중에는 새 후보를 계속 만들지 않는다.

실험 준비·시작은 기존 전체 발송 연결을 바꾸지 않는다. 승인 연결 없는 규칙도 실험 안에서만 A/B 버전을 고정하고, 실험 밖의 일반 발송은 기존 경로를 유지한다. 전체 발송 연결은 사람의 최종 적용 단계에서만 새 후보로 변경한다.

검증: 전체 단위 테스트 1,031개, TypeScript·변경 코드 ESLint·최적화 빌드 통과. `node --import tsx scripts/check-copy-automation.cjs`는 기존 실험 37개와 자동 준비 17개 시나리오를 외부 통신 없는 PGlite에서 검사한다. 자동/수동 개설, 수동 적용 전 B 미연결, 승인 연결 없는 규칙의 실험 배정과 전체 연결 미변경, 최종 적용 오류의 전체 롤백, 반복 적용, 사람 정정 우선, 사용량 제한, 품질 미달 보류를 확인한다. 테스트 모델의 점수·가상 과거 발송은 기능 검사용 합성 데이터이며 실제 문구 품질이나 실험 성과의 근거가 아니다. 실제 고객 시험 발송은 0건이다.

## 회사 확인·등급 수동 등록 제거 (2026-10-14)

사용자가 `회사 확인과 등급` 기능 삭제와 운영 반영을 요청했다. 탭·개별 입력·CSV 등록 컴포넌트와 관리 API, 회사·등급 저장 함수를 제거했다. 자동 후보 준비에서도 별도의 회사 등록을 수행하지 않는다.

- 새 수동/자동 실험은 불변 config에 `analysisUnit: recipient`를 저장한다. 회사 정보 유무와 관계없이 정규화한 고객 이메일을 기준으로 비교 표본을 배정한다. 같은 회사의 서로 다른 이메일은 별도 고객이며 같은 이메일은 한 번만 배정한다. 기존 발신 프로필·예정일별 50:50 균형 배정은 유지한다.
- 기존 테이블 제약과 인덱스를 유지하기 위해 새 배정의 `company_key`에는 `recipient:` 접두사와 고객 키를 저장한다. 새 실험의 외부 접촉 판단은 이메일을 사용하고 기존 회사 연결은 조회하지 않는다. 기존 실험은 저장된 회사 단위 배정·등급·비교/참고 집계를 그대로 해석한다. 데이터 삭제나 DB 마이그레이션은 없다.
- 이전 자동 준비 초안은 불변 조건을 수정하지 않고 새 이메일 기준 초안을 만들어 준비 회차에 연결한다. 이미 시작한 실험의 조건과 배정은 바꾸지 않는다.
- 시작 전 미리보기는 비교 대상 고객·이메일 중복 제외를 표시한다. 회사 확인 열과 등급별 표시를 제거했다. 내부 이메일·도메인 제외를 유지하고, 명단 회사명이 조직/사업명과 일치하는 내부자도 미리보기와 실제 준비에서 제외한다.
- 표본·14일 관찰·회신 품질 관문과 사람의 최종 채택은 유지한다. 운영 DB 직접 조회 및 실제 고객 시험 발송은 하지 않는다.

검증: 단위 테스트 1,031개, 격리 PGlite 실험 40개·자동 준비 18개, 변경 코드 ESLint·TypeScript·최적화 빌드 통과. 회사 정보 없는 가상 고객 1,000명의 500:500 배정, 개인 메일의 비교 표본 포함, 기존 같은 회사 등록의 새 배정 미관여, 중복 이메일 고정 배정, 내부자 제외, 기존 회사 단위 실험 분모 보존, 이전 자동 초안의 새 기준 재생성과 원본 불변을 확인했다. 실제 로컬 UI에서 탭 제거, 비교 대상 1,000명 미리보기, 수동 시작 및 등록 없는 A100/B100 배정을 확인했다. 실제 고객 시험 발송 0건.

배포 상태는 실행 확인 뒤 추가 기록한다.

## 통계 구현 근거

차이의 95% 구간은 독립 Wilson 구간을 결합하는 Newcombe 방법을 사용한다. 사건이 0건이어도 구간 폭을 0으로 단정하지 않는다. [원 논문](https://doi.org/10.1002/(SICI)1097-0258(19980430)17:8%3C873::AID-SIM779%3E3.0.CO;2-I)
