# 고객 여정 강조·핵심 리드 담당자 태그

메일에서 들어와 관심을 보이다 멈춘 고객의 카드가 일반 방문과 구별되지 않았습니다. 이제 행동 근거를 카드 상단에 표시하고, 특히 강한 이탈 리드는 지정 담당자에게 실제 Google Chat 멘션으로 확인을 요청합니다. 업종·회사 규모를 임의로 추정하지 않고, ICP 표시가 없어도 행동으로 판정합니다.

## 개발자가 먼저 볼 내용

- `dev` 변경이며 운영 배포는 하지 않았습니다. 기존 초안 PR #6에서 검토합니다. 고객 여정 변경에는 추가 DB 마이그레이션이 없습니다. PR에 앞서 포함된 무작위 메일 예약 기능의 `0078` 마이그레이션은 별도 인계서를 따릅니다.
- **주황 강조**: 핵심 ICP로 명시한 고객, 신청 입력·상담/데모/체험 버튼 행동, 또는 여러 관심 영역을 충분히 검토한 고객의 이탈.
- **빨강 + 담당자 태그**: 실제 신청 시작 또는 상담/데모/체험 버튼 클릭, 가격·사례·상세 중 2종 이상 검토, 2분 이상 체류 및 최소 90초에 걸친 복수 활동을 모두 요구합니다. 점수 조건도 아래와 같이 적용합니다.
- 디자이너 하이어 고객여정 → **이효정**, 백오피스랩 고객여정 → **양윤지**. 기존 웹훅의 스페이스 ID와 확인한 Google 사용자 ID를 연결했습니다. 같은 이름의 다른 사업이나 미등록 스페이스로 담당자를 추정하지 않습니다. 스페이스를 새로 만들거나 담당자가 바뀌면 `customer-journey-owner.ts`를 갱신해야 합니다.
- 같은 고객의 태그는 사업별로 **24시간 1회**입니다. 그 안의 새 방문 카드는 같은 기존 스레드에 계속 보냅니다. 일반 강조는 멘션하지 않습니다.
- 내부자·공유 방문자·기존 반복 방문·수신거부는 카드 전송과 순위 집계에서 제외합니다. 이미 신청/구매한 고객은 완료 카드로 처리하고 순위·이탈 태그에서 제외합니다.

## 행동 기준

| 근거 | 점수/조건 |
| --- | --- |
| 신청 입력·AI 신청 시작 이벤트 | 40점 |
| 상담·데모·체험·미팅·전화 버튼 클릭 | 30점 (신청 시작과 중복 가산 안 함) |
| 신청 페이지 조회만 확인 | 15점; 이것만으로 긴급 태그 불가 |
| 가격·사례·서비스 상세 검토 | 서로 다른 종류마다 10점, 최대 30점 |
| 지속적인 활동 | 2분 체류 + 90초 이상 간격에 걸친 3회 이상 활동이면 15점. 1분 체류 + 30초 활동이면 10점 |
| 같은 고객 메일로 30분 이상 간격의 재방문 | 10점 |
| CRM에 명시된 핵심 ICP | 보조 10점; 없어도 행동으로 핵심 리드 판정 가능 |

관심 영역은 페이지를 15초 이상 보거나 영역의 측정 체류가 10초 이상일 때 인정합니다. 동일 영역 반복·빠른 스크롤·소개서 다운로드·신청 페이지를 연 것만으로 긴급 리드가 되지 않습니다. 신뢰/사례 버튼 클릭은 직접적인 사례 검토 신호로 인정합니다. 영역 합계로 총 체류 시간을 부풀리지 않습니다.

- 비교 고객이 **20명 이상**이면 같은 사업의 최근 30일 유효 고객 중 **상위 5% + 75점 이상**일 때 긴급 대상입니다. 명시된 핵심 ICP는 상위 5% 조건을 대체할 수 있지만 행동 조건과 75점 조건은 모두 필요합니다.
- 비교 고객이 **20명 미만**이면 행동 조건을 충족하면서 **85점 이상**인 경우만 긴급 대상으로 봅니다. 즉, 신청 시작 + 가격/사례/상세 세 가지 검토 + 지속 활동이면 ICP 없이도 해당합니다.
- 비교는 이 버전의 판정 결과가 있는 고객부터 쌓이며, 배포 전의 기존 카드를 소급해서 순위로 만들지 않습니다. 같은 수신 이메일의 여러 레코드·세션은 한 명으로 합칩니다. 다른 사업·조직은 섞지 않고 동점은 낮은 점수보다 앞선 비율만 계산합니다. 통계가 부족하면 상위 몇 %라는 표현을 만들어내지 않습니다.
- 주황 강조는 핵심 ICP이거나, 입력 시작/상담 버튼 행동이 있거나, 2종 이상의 영역을 검토하고 35점 이상인 경우입니다.
- 마지막 활동 후 10분간 추가 활동이 없어야 이탈 추정입니다. 이탈 이유나 구매 가능성을 확정한 표현은 사용하지 않습니다.

## 내부자·오탐 방지

- `matchesplan.com`, `matchesplan.cloud` 및 하위 도메인, 해당 조직의 사용자/조직 멤버 이메일, 발신 프로필 주소를 제외합니다. 개인 Gmail 계정도 조직 사용자로 등록되어 있으면 제외됩니다. 다른 조직의 사용자 이메일을 이 조직의 내부자로 취급하지 않습니다.
- 추가 내부 도메인은 선택적으로 `JOURNEY_ALERT_INTERNAL_DOMAINS`에 쉼표로 지정할 수 있습니다. Gmail/Naver 같은 공용 메일 도메인은 넣지 않습니다.
- 메일 수신자뿐 아니라 트래커에서 identify한 이메일, 동일 방문자에 연결된 CRM/메일 주소도 확인합니다. 같은 사이트에서 한 브라우저가 여러 고객 이메일에 연결되면 고객 한 명으로 단정하지 않고 제외합니다. IP가 같다는 이유로 제외하지 않습니다.
- 메일보다 앞선 방문이 3회 이상인 경우 제외하되, 같은 고객의 이전 메일에서 발생한 재방문은 유지합니다.
- 현재 세션 외에도 같은 사이트 방문자의 최근 30일 완료 신호와 CRM 기본 마케팅 퍼널/이력을 확인합니다. 대기/재시도 중 내부자로 식별되거나 신청을 완료하면 현재 상태로 다시 판정합니다. 최근 활동이 있으면 보내지 않고 기다립니다.
- 뒤늦게 내부·공유·전환 완료로 확인한 고객은 기존 판정의 순위 집계 자격도 제거합니다. 기존 카드와 멘션 기록은 보존합니다.
- 식별되지 않은 개인 기기에서 직원이 고객에게 전달된 링크 하나만 열면 완벽한 구분은 어렵습니다. 식별 이메일이나 공유 클릭 신호 없이 내부자라고 추측하지 않습니다. 사내 시험에는 조직에 등록된 이메일을 사용합니다.

## 전송과 검토

사용자 본문의 `<users/...>`는 기존처럼 차단하며, 서버가 지정한 숫자 사용자 ID 한 명만 별도 옵션으로 붙입니다. Google Chat은 사용자 멘션을 카드 HTML이 아닌 메시지의 `text`에 넣도록 정의하고, 이메일 별칭은 사용자 인증을 요구하므로 확인한 숫자 ID를 사용했습니다. [Google Chat 공식 형식 문서](https://developers.google.com/workspace/chat/format-messages#mention_users_in_a_text_message)

태그 요청 직전에 알림 상태를 결과 미확인으로 기록합니다. 응답 전 서버가 종료되거나 Google 응답이 불명확하면 자동 재태그하지 않습니다. 확정 실패만 기존 재시도 정책을 따릅니다. 순위·태그 이력은 기존 `message` JSONB에 저장하고, API 요청에는 `text`/`cardsV2`/`thread`만 보냅니다.

기존 고객 여정 모드·사업 허용 목록·웹훅을 그대로 사용합니다. 개발 서버의 live 전환이나 운영 서버 변경은 하지 않았습니다. 실제 Google Chat 멘션 전송은 시험하지 않았으며, 담당자 선택기의 ID 확인과 격리된 전송 본문 검증까지 완료했습니다. 실제 운영 반영 후 해당 조건의 새 방문부터 적용됩니다.

단위 테스트 145개 및 PGlite의 실제 후보/집계/전송 직전 재확인 SQL 6개 시나리오를 통과했습니다. 통합 검사는 조직 격리, 여러 조직에 가입한 내부 사용자, 개인 메일 내부자, identify, 공유 브라우저, 스캐너, 수신거부, CRM 완료, 담당자 라우팅, 태그 24시간 제한, 불명확 응답, 대기 중 상태 변화, 비교 표본 및 dry_run을 확인합니다. 잠금 함수만 단일 메모리 DB에 맞춰 대체합니다. 모든 데이터가 가상이며 외부 요청과 운영/개발 DB 접근은 0건입니다. 격리 검사 의존성 설치 방법은 실행기 상단에 있습니다.
